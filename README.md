# Excel Bro

一个本地优先的 Excel AI 助手原型。它可以读取当前工作簿，或用户指定文件夹中的多个 Excel 文件，把自然语言需求交给本地 Python 服务生成可审查的操作计划，再由 Office.js 或本地文件服务在用户确认后执行。

## 当前闭环

1. 用户选择当前工作簿，或通过系统目录选择器定位一个文件夹。
2. 插件读取可用文件和工作表，用户按本次任务进行多选。
3. 用户用中文描述分析需求。
4. 配置模型后，Excel Agent 会按需查找字段、读取区域并通过工具循环生成结构化操作计划；未配置模型时使用仅支持明确命令的“基础模式”。
5. 插件展示摘要；详细假设、风险和写入动作可以按需展开。
6. 用户确认后执行；支持工作表、区域、公式、格式、筛选、验证规则、表格、图表、透视表和常见对象操作。
7. 执行完成后重新读取实际工作表或磁盘文件，按验收条件检查工作表存在/删除、区域值、公式或清空结果，并在对话中展示验证结果。
8. 验证成功的计划可以经过固化资格检查后保存为 v2 参数化工作流。

旧计划不需要手动迁移：服务和插件会根据 `createWorksheet`、`deleteWorksheet`、`writeTable`、`writeValues`、`writeFormulas` 和 `clearRange` 自动生成确定性验收条件。验收范围必须与预期矩阵尺寸一致，而且只能检查计划实际操作的工作表。

## 表格操作能力

Excel 内执行支持：

- 工作表新建、删除、切换；
- 单元格/区域值和公式写入、清空、插入、删除、复制；
- 多关键字排序、值筛选及清除筛选；
- 填充色、字体、数字格式、边框、对齐、行高列宽、自动适配；
- 合并/取消合并、冻结窗格、数据验证、条件格式；
- 超链接、批注、备注、名称区域；
- Excel 表格、图表、数据透视表、图片和形状。

文件夹模式通过 `openpyxl` 支持其中可可靠保存到 `.xlsx/.xlsm` 的动作，并在修改源文件前自动备份。Office.js 或 `openpyxl` 没有安全接口的动作会明确报错；当前不执行 VBA/宏、任意脚本或外部程序。不同 Excel 版本对备注、形状等较新的 API 支持不同，具体失败会显示在对应执行步骤。

本地聚合分析会区分直接回答和写入请求，并支持平均、合计、最大、最小等同类操作。多张工作表含有同名字段时，不会默认混合数据：用户可以明确要求“合并计算”或“分别计算每张表”。超过快照上限的计算会标明只覆盖前 200 行；明确指定输出工作表或起始单元格时，精简结果计划会使用该目标位置。

计算和单元格查询回答会附带结构化结果上下文，并由任务窗格传入下一轮请求。因此“把这个平均值放在一个新子表中”“把刚才的查询结果写到汇总表 D5”等后续表达会复用上一轮结果，不会重新扩展成完整统计。上下文缺失或单数指代对应多项结果时，服务会先说明歧义。

任务窗格会在每次发送消息时重新读取当前活动工作表和选区。简繁体命令及“输出到/输出在/写到/放在”等常见表达会先归一化；“计算平均分，然后将结果输出在表格中相应位置”这类复合请求会把单个结果写入当前选区的左上角，而新工作表或多项结果仍使用结构化表格。

极值数值和极值记录会分别处理：“某字段的最大值是多少”返回最大值，“哪个对象的该字段最大”返回最大值所在行的对象。记录查询支持任意文本标识字段、并列结果、前/后 N 项、合并或分别处理多张工作表，并可作为结构化结果继续写入 Excel。

没有配置模型时，服务会对读取到的数据执行真实的本地数值统计；如果工作簿为空，则明确提示缺少数据，不会生成假的“分析计划”。开放式问答和根据业务语义自主分析仍需要配置模型。

模型规划不是一次性提示词生成 JSON，也不会在代码中硬编码行业字段。首次决策只接收用户明确选择的工作表范围、由 Excel 本地扫描识别出的字段结构、最近对话、上一轮结构化工具意图和上一轮紧凑结果；原始数据行不会进入意图识别请求。模型负责理解承接式追问；存在会改变结果的歧义时，任务窗格会显示推荐选项，并始终保留独立的“其他想法”输入框。需求明确且属于查询或统计时，模型会申请内置 `query_table` 工具，由 Excel 端在授权范围内读取完整数据并完成筛选、分组、计数、求和、平均、极值、占比和排序，只把紧凑结果与计算来源交回模型。工具字段或参数不匹配时允许模型修正一次；模型结构化输出无效时也会自动修复一次，不会直接向用户暴露协议错误。格式或写入任务则继续进入受类型系统约束且必须预览的 Agent 规划。用户要求“写公式”时会保留为 `writeFormulas` 动作，不会先在服务端算出静态值再冒充公式。无模型时只提供能力有限且明确标识的基础模式。

前端统一通过 `/api/turn` 推进一轮对话。需求确认、用户补充、本地工具修正和最终回答共享同一个 `turnId`；后端为轮次维护带过期时间和容量上限的状态，记录它当前处于澄清、工具调用、等待完成或已完成阶段。相同轮次、相同完成参数的重复请求直接返回已缓存结果，不会再次调用模型或生成第二份操作计划；已完成轮次若收到不同参数则会明确拒绝，要求创建新轮次。旧 `/api/intent` 与 `/api/plan` 暂时保留用于兼容。

内置数据工具使用结构化错误协议，区分不支持的工具、越权范围、调用上限和字段不存在等情况，并携带是否允许修正及实际可用字段。只有可修正错误才会再交给模型调整一次，确定无法恢复的错误会直接停止，避免盲目重试。统一对话接口也返回稳定的错误码、可读消息和可重试标记，任务窗格不会再把整段服务端 JSON 当作错误文案显示。

项目级读取、图片、对话、意图预览、固化工具、Agent 和轮次上限集中定义在 `config/capabilities.json`，后端通过 `/api/capabilities` 公布相同配置，避免前后端分别维护不一致的数字。

长耗时请求会在对话区展示真实阶段和累计耗时，包括本地字段扫描、模型需求确认、本地数据读取与计算、回答生成或操作预览。已完成步骤会保留在当前进度卡片中，并显示工作表数量和实际扫描行数；界面不使用无法保证准确的虚假百分比。

“我的工具”保存的是结构化工作流模板，不是任意脚本。保存前会检查固定写入值、删除/清空/覆盖、内嵌图片和快照式验收条件：内嵌图片禁止固化；固定内容和破坏性操作必须由用户分别确认。v2 工具使用显式绑定参数化来源工作表、输出工作表、源数据范围，以及拆分汇总和数据透视表中的字段；再次运行时会本地刷新工作簿结构，自动采用所选来源表的实际使用范围，为重名输出表建议新名称，联动字段选择并进行存在性、名称冲突和参数有效性预检，然后编译成一份新的 `AnalysisPlan` 供用户预览。已有 v1 和早期 v2 工具会在首次读取时补齐当前参数定义，删除后的工具不会被旧存储重新恢复。

模型接入不强制要求 API Key：配置服务地址和模型名后就会启用模型，因此 Ollama、LM Studio 等无鉴权的本地 OpenAI-compatible 网关也能直接使用。环境变量既支持项目自己的 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`，也兼容常见的 `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_API_KEY`；两套同时存在时优先使用 `AI_*`。

任务窗格顶部提供模型选择器。`AI_MODEL` 是默认模型，`AI_MODELS` 可以用英文逗号声明同一 OpenAI-compatible 服务地址和 API Key 下允许切换的其他模型，例如：

```env
AI_BASE_URL=https://api.moonshot.cn/v1
AI_API_KEY=你的密钥
AI_MODEL=kimi-k3
AI_MODELS=kimi-k2.6,另一个已开通的模型ID
AI_VISION_MODELS=kimi-k3,kimi-k2.6
```

前端只会展示服务端允许列表，不接收或保存 API Key；每次请求都会携带本次选择的模型 ID，后端再次校验后才会调用。选择“基础模式”时不会请求外部模型。服务状态和模型列表每 5 秒自动刷新，因此先打开 Excel、后启动本地服务也能自动恢复连接。

支持视觉输入的模型会在输入框中启用图片按钮。用户可以选择、拖入或直接粘贴
PNG、JPEG、WebP 截图；一次最多 3 张，单张发送前会压缩到 4 MB 以内。图片只随
当前请求发送，不会写入本地聊天记录。所有视觉模型都必须在
`AI_VISION_MODELS` 中显式声明，系统不会根据模型名称猜测能力。

任务窗格采用持续聊天界面：顶部显示当前工作簿上下文，中间保留消息和计划记录，底部输入框固定可用。旁加载后，Excel 功能区会出现 **Excel Bro** 标签，点击 **打开 AI 对话** 即可随时唤起任务窗格。

## 本地启动

### 1. 安装前端依赖

```powershell
npm install
```

### 2. 创建 Python 环境

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r server\requirements.txt
Copy-Item server\.env.example server\.env
```

如果需要真实模型，在 `server/.env` 中填写 OpenAI-compatible 服务地址和模型名。云端服务再填写密钥；本地无鉴权网关可以不填。Kimi、其他 OpenAI-compatible 服务或本地模型网关都可以通过同一接口接入。

插件最多读取每张工作表的前 200 行、前 30 列；超过上限时会把工作表标记为截断，AI和本地统计都必须在结果中说明这一点。

### 文件夹模式

在工作表选择卡片中切换到“文件夹”，点击“选择文件夹”。本地服务会递归扫描最多 100 个 `.xlsx`、`.xlsm` 文件，然后按“文件 → 工作表”展示供多选。

- 未指定目标文件的新结果写入所选目录下的 `Excel Bro 结果.xlsx`。
- 如果计划明确修改已有文件，保存前会在同一目录生成带时间戳的 `.excel-bro-backup-*` 备份。
- 临时锁文件、既有备份文件和不支持的旧 `.xls` 文件不会参与扫描。

### 3. 启动本地服务

```powershell
npm run dev:server
```

### 4. 启动任务窗格

首次运行开发证书工具时，Windows 会请求信任本地 HTTPS 证书。

```powershell
npm run dev:addin
```

另开一个终端，把插件旁加载到 Excel：

```powershell
npm run start:excel
```

停止旁加载：

```powershell
npm run stop:excel
```

修改过 `manifest.xml` 后，需要先停止旧的旁加载，再重新执行 `start:excel`；仅刷新任务窗格不会更新功能区按钮。

也可以直接打开 `https://localhost:3000` 在浏览器中使用内置演示工作簿调试界面。

## 安全边界

- 本地服务默认只监听 `127.0.0.1`。
- 模型只能返回白名单内的 Excel 动作，响应还会经过 Pydantic 和前端双重校验。
- 删除、清空和覆盖动作会在预览中显示风险提示；写入前必须由用户确认。
- 不开放 VBA/宏、网络脚本、任意 JavaScript 或外部程序执行。
