## 当前闭环

1. 用户选择当前工作簿，或通过系统目录选择器定位一个文件夹。
2. 插件读取可用文件和工作表，用户按本次任务进行多选。
3. 用户用中文描述分析需求。
4. 配置模型后，Excel Agent 会按需查找字段、读取区域并通过工具循环生成结构化操作计划；未配置模型时明确引导「添加模型」，只保留已知地址的确定性命令。
   澄清选项会区分“补充原需求”和“替换旧要求”：改变拆分维度或输出结构时，新确认
   会完整覆盖冲突的旧指令。计划格式修正轮只重新提交受控结果、不重新开放读取；
   意图、规划及格式修复默认使用供应商输出额度，不再分别强设 1200/4000/2000 token。
5. 插件展示摘要；详细假设、风险和写入动作可以按需展开。
6. 系统使用本次明确授权的工作表集合预检整份计划；未授权现有表会在任何写入前被拒绝，真正的新输出表仍可创建。通过后再执行工作表、区域、公式、格式、筛选、验证规则、表格、图表、透视表和常见对象操作。
7. 执行完成后重新读取实际工作表或磁盘文件，结果明确区分“已验证成功”“已执行但无法独立验证”和“验证失败”；若中途失败，还会展示已成功、失败和未执行的动作。
8. 验证成功的写入计划可以保存为 v2 参数化工作流；确定性查询也可以保存为固化查询，在当前工作簿或文件夹中直接本地重跑。

`finish_reason=length` 单独标记 `output_length`，不接受其中任何工具或计划，
不再降额重试或要求用户简化需求；它也可能来自上下文容量，不能只凭该标志判定是推理耗尽。

旧计划不需要手动迁移：服务和插件会根据工作表、写值/公式、清空、排序、筛选、表格、常用格式、边框、数据验证、冻结窗格和数据透视表动作自动生成确定性验收条件，图表则在 Office.js 创建后记录真实对象名称。排序会检查执行后的真实值顺序，筛选会读取真实 AutoFilter 条件，表格会核对真实名称、范围和表头状态；格式和验证动作会核对保存后的具体属性；当前工作簿的图表和数据透视表还会核对真实数据源、位置与字段配置。暂时无法稳定核对的条件格式和文件夹图表等动作仍明确标记为未独立验证。验收范围必须与预期矩阵尺寸一致，而且只能检查计划实际操作的工作表。

## 表格操作能力

Excel 内执行支持：

- 工作表新建、删除、切换；
- 单元格/区域值和公式写入、清空、插入、删除、复制；
- 多关键字排序、值筛选及清除筛选；
- 填充色、字体、数字格式、边框、对齐、行高列宽、自动适配；
- 合并/取消合并、冻结窗格、数据验证、条件格式；
- 超链接、批注、备注、名称区域；
- Excel 表格、图表、数据透视表、图片和形状。

文件夹模式使用 pandas 对用户已授权的“文件 ID + 工作表 ID”执行完整数据查询，使用 `openpyxl` 处理可可靠保存到 `.xlsx/.xlsm` 的动作。多文件写入先检查可用空间，全部保存到同目录临时文件，再集中保存执行前恢复点并替换目标；替换或回滚中断时保留可核对资料，不把部分完成冒充为原子成功。Office.js 或 `openpyxl` 没有安全接口的动作会明确报错；当前不执行 VBA/宏、任意脚本或外部程序。不同 Excel 版本对备注、形状等较新的 API 支持不同，具体失败会显示在对应执行步骤。

本地聚合分析会区分直接回答和写入请求，并支持平均、合计、最大、最小等同类操作。当前工作簿按 5,000 行分块读取并由增量累加器直接计算，不会在内存中重新拼接完整数据矩阵，同时显示进度并可安全取消；文件夹查询由 pandas 读取授权工作表的完整数据，保留 Excel 中带前导零的格式化编码，并支持多文件合并、去重、结构化关联和分组。快照只用于模型上下文，确定性查询不受前 200 行快照上限限制。

计算和单元格查询回答会附带结构化结果上下文，并由任务窗格传入下一轮请求。因此“把这个平均值放在一个新子表中”“把刚才的查询结果写到汇总表 D5”等后续表达会复用上一轮结果，不会重新扩展成完整统计。上下文缺失或单数指代对应多项结果时，服务会先说明歧义。

任务窗格会在每次发送消息时重新读取当前活动工作表和选区。简繁体命令及“输出到/输出在/写到/放在”等常见表达会先归一化；“计算平均分，然后将结果输出在表格中相应位置”这类复合请求会把单个结果写入当前选区的左上角，而新工作表或多项结果仍使用结构化表格。

极值数值和极值记录会分别处理：“某字段的最大值是多少”返回最大值，“哪个对象的该字段最大”返回最大值所在行的对象。记录查询支持任意文本标识字段、并列结果、前/后 N 项、合并或分别处理多张工作表，并可作为结构化结果继续写入 Excel。

没有配置模型时不会退回规则模式猜测需求：服务会明确提示先添加模型连接，避免把一次“没有可用模型”伪装成正常回答。已固化的确定性能力仍可独立使用，包括清空区域、已知地址的写值与写公式，以及已保存的固化查询；它们由本地工具确定性执行，不需要模型参与。

WPS 任务窗格与 Excel EB 共用同一套产品样式和主要交互结构，模型、新对话、工具、备份、格仔、历史、数据范围和输入区不再维护两套设计。WPS 会在发送时重新解析“跟随当前”的活动表；固化查询在本轮授权范围内直接由本地确定性执行器运行。宿主尚未支持的工作目录、图片输入和结构动作会明确禁用或拒绝，不会伪装为已经可用。

Excel 与 WPS 的写入能力共用 `AnalysisPlan`、服务端计划校验，以及前端 `planCore.ts` 的 A1 区域和矩阵语义；各自的宿主适配器负责实际读写、恢复点和回读。WPS 写入仅在经过真实宿主验收的版本与动作上开放，核心逻辑复用不会跳过这道安全门槛。
开发调试加载项暂时允许 WPS 实机报告的 JSAPI `Application.Version="12.0"` 进入受控写入流程，以便在独立测试工作簿完成写入、回读和撤销验收；原来误用安装目录版本的正式白名单已清空，正式构建仍拒绝写入，且预览确认、授权范围与动作白名单照常生效。

普通问候和能力咨询由模型直接回复，不再强制弹出操作类别卡片；真正需要澄清的任务才提供选项和自由输入。规划阶段（含 Agent SDK）也可返回结构化填写卡，每项缺少的信息独立输入，填写完整后点击「提交补充并生成预览」；不会直接写表，也不靠识别助手文本生成表单。WPS 会先读取授权表的候选表头判断意图，仅在确定需要查询数据时读取完整数据行。

模型规划不是一次性提示词生成 JSON，也不会在代码中硬编码行业字段。首次决策只接收用户明确选择的工作表范围、由 Excel 本地扫描识别出的字段结构、最近对话、上一轮结构化工具意图和上一轮紧凑结果；原始数据行不会进入意图识别请求。模型负责理解承接式追问；存在会改变结果的歧义时，任务窗格会显示推荐选项，并始终保留独立的“其他想法”输入框。用户点选推荐确认项后，该项直接成为最终口径，不再送回意图模型重复确认；规划请求只暴露提交工具，并根据准确表头生成执行时读取完整数据的计划，避免 200 行快照和重复读取消耗 token。需求明确且属于查询或统计时，模型会申请内置 `query_table` 工具，由 Excel 端在授权范围内读取完整数据并完成筛选、分组、计数、求和、平均、极值、占比和排序，只把紧凑结果与计算来源交回模型。工具字段或参数不匹配时允许模型修正一次；模型结构化输出无效时也会自动修复一次，不会直接向用户暴露协议错误。格式或写入任务则继续进入受类型系统约束且必须预览的 Agent 规划。用户要求“写公式”时会保留为 `writeFormulas` 动作，不会先在服务端算出静态值再冒充公式。未配置模型时普通请求会明确失败并引导配置，不会静默降级为规则模式，也不会擅自改用其他供应商。

前端统一通过 `/api/turn` 推进对话。意图阶段的需求确认和用户补充可沿用同一个 `turnId`；后端为轮次维护带过期时间和容量上限的状态，区分澄清、工具调用、等待完成和已完成。规划可返回普通计划、回答、结构化澄清，或不含单元格值的 `local_plan_rule`，由 Excel/WPS 在已授权工作表内本地计算并预览确认。规划澄清不会将对话标成已完成；用户补充后，两端带完整原需求开始新的规划轮次，避免改动既有流式任务的请求指纹。相同轮次、相同完成参数的重复请求可返回缓存；真正已完成的计划若收到不同参数则拒绝复用。旧 `/api/intent` 与 `/api/plan` 暂时保留用于兼容。

Excel 与 WPS 在本地计算列映射时若发现实际来源值未被规则覆盖，均显示同一套仅在当前面板内存保存的结构化补充卡；用户可逐项指定目标值，或确认分隔符、补齐拆分项映射并明确所有目标的优先顺序。补充后重新读取已授权源列并生成新的待确认预览，仍不会自动写入，也不会为了修正本地缺口再调用模型。原始来源值、用户补充映射和目标矩阵不会**随澄清卡**落盘或发给模型；生成预览后的 Excel 计划仍遵循现有聊天历史持久化策略。自动化已覆盖 WPS 完整交互与 Excel 的共享表单/计算，宿主实机验收仍需分别进行。服务端提前发现的语义缺参另走需求澄清卡，不属于这个本地闭环。

内置数据工具使用结构化错误协议，区分不支持的工具、越权范围、调用上限和字段不存在等情况，并携带是否允许修正及实际可用字段。只有可修正错误才会再交给模型调整一次，确定无法恢复的错误会直接停止，避免盲目重试。统一对话接口也返回稳定的错误码、可读消息和可重试标记，任务窗格不会再把整段服务端 JSON 当作错误文案显示。

项目级读取、图片、对话、意图预览、固化工具、Agent、轮次上限和 Excel 批处理参数集中定义在 `config/capabilities.json`，后端通过 `/api/capabilities` 公布相同配置，避免前后端分别维护不一致的数字。拆分聚合默认每 25 张结果表同步一次 Office.js，减少大量拆表时的逐表往返；写入完成后会重新读取每张结果表的表头、分组字段、指标和占比，超过 500 行时分块验收，不再只检查工作表是否存在。

长耗时请求会在对话区用默认展开的单层时间线展示真实阶段和累计耗时，包括需求理解、受控工具读取、预检、撤销数据捕获、逐动作执行、拆分子表、集中备份、原子保存和独立验证。每一步从开始时就出现并原位更新，同时显示真实工具名、Excel 动作、授权范围内的目标、安全参数摘要以及理解依据、决策、冲突和纠偏记录；这些记录由受控代码构造，不包含模型隐藏思维、凭据或工具原始数据行。实时过程和已完成消息使用同一布局，用户可手动收起整个过程。用户停留在底部时界面自动跟随新步骤；向上阅读旧内容时保持当前位置并提示返回最新进度。文件夹流式执行使用持久 `operationId` 幂等保护，断线或任务窗格刷新后以同一标识和最后事件序号补收进度，不会重复写文件；服务重启后可重放已完成结果，现场不完整的任务只进入核对，不自动重跑。已保存工作簿中的 5 类确定性区域写入也会逐动作保存写前状态与完成回执；刷新后只有在工作簿身份和实际目标范围可确认时才允许显式续跑。界面只在执行器提供真实计数时显示定量进度。

待答澄清复核授权目标、表头与宿主身份证据。WPS 包装对象证据不足时，先在分析之前取得当前文件/表范围的显式目标同意；同一已确认范围的补充和追问可据此重新读取与生成预览，但不把名称/表头相同当成原生对象相同的证明，写入仍执行独立的强身份和快照守卫。实际目标冲突或没有有效同意时暂停并保留需求与答案，不擅自操作新文件。完整路径与私有目标键只在内存比对，不写入存储、请求体、日志或错误文案；也不会为了验身份重读数据行或扩大已勾选的工作表范围。会话关闭/重载不恢复这个弱同意。

**任务中断后继续（第一阶段）**：需求已经说清楚、范围也勾好了，任务却因为断网、服务重启或任务窗格重载停在半路时，不再只剩一句"已失效，请重新发送需求"。中断卡绑定原任务与原消息，如实分开显示**中断原因 / 已保留的信息 / 原表写入状态**，并给出「继续任务」与「取消任务」；写入状态未知时不会显示"原表未修改"。阶段、阻塞原因、能否安全继续是三件独立的事，共享口径在 `packages/core/src/taskResume.ts`，只有存在安全检查点时才说"从上次保存的进度继续"，否则一律说明会**重新生成预览**，不冒充精确续跑。恢复记录是版本化 + **显式白名单**结构：只保存任务定位、阶段、原需求与用户显式确认的信息，单元格内容、目标矩阵、宿主对象引用与完整路径**结构上无法进入**；缺原需求时明确报"无法恢复"，不用摘要冒充完整任务。WPS 侧重开后仍按既有判据收敛为"无法确认"（不谎称范围已变），但提供「确认此范围并继续」——它重新读取当前工作簿/工作表/表头、捕获新的对象身份并推进授权版本，用保留的原需求与已提交回答发一轮全新请求，因此不会再次被同一个旧对象引用检查卡住；已提交的回答跨重载存活，不重复询问。Excel 侧数据范围改为**草稿与已提交授权分离**：勾选只改草稿，「确认范围」才按当前真实工作簿复核并提交，「取消范围编辑」一字不改已提交授权。**恢复规划不等于写入完成**：继续之后仍要经过白名单计划校验、宿主执行与回读，再供用户审阅。第一阶段不包含 WPS 写入中断后的自动续写、跨设备恢复，也没有豁免确认的"一键重做"。

“我的工具”保存的是结构化工作流或确定性查询模板，不是任意脚本。写入工具仍编译为新的 `AnalysisPlan` 并经过预览、确认和验收；固化查询保存字段、筛选、分组、指标、合并方式、来源和预期输出结构，重复运行时直接调用 TypeScript 或 pandas 执行器。字段、来源模式或输出结构变化时会停止本地执行并要求重新确认。诊断记录会验证正常重复运行的模型调用次数为 0。

模型接入不强制要求 API Key：配置服务地址和模型名后就会启用模型，因此 Ollama、LM Studio 等无鉴权的本地 OpenAI-compatible 网关也能直接使用。环境变量既支持项目自己的 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`，也兼容常见的 `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_API_KEY`；两套同时存在时优先使用 `AI_*`。

新安装不会预置 Kimi 或任何其他外部模型：任务窗格在没有真实模型连接时显示「添加模型」入口，并通过首次引导提示配置模型；模型列表只列出你实际配置的连接，不再提供任何占位模型。窗格较窄时会先引导用户把面板拉宽（向左拖动面板左边缘），再承接“添加模型”引导；窗格本身够宽时直接进入模型引导，拉宽步骤可以跳过、不会阻塞。同一个顶部模型入口同时负责选择、添加和管理模型；添加成功后引导自动消失。`AI_MODEL` 仍可作为旧环境配置的默认模型，`AI_MODELS` 可以用英文逗号声明同一 OpenAI-compatible 服务地址和 API Key 下允许切换的其他模型，例如：

```env
AI_BASE_URL=https://api.moonshot.cn/v1
AI_API_KEY=你的密钥
AI_MODEL=kimi-k3
AI_MODELS=kimi-k2.6,另一个已开通的模型ID
AI_VISION_MODELS=kimi-k3,kimi-k2.6
```

点击顶部模型入口可以添加多个独立模型连接，例如分别配置 Kimi、DeepSeek、OpenAI 或本地网关，也可进入完整管理页。每个连接独立保存名称、服务地址、模型 ID、API Key 和图片能力，随后自动出现在同一个模型菜单中。WPS 的新增表单会立即打开，并异步检查 Excel/WPS 共用的本机连接；检查失败会明确提示，不会误报为未配置。同一模型 ID 和服务地址也能新增独立连接，重复模型 ID 会显示 `(1)`、`(2)` 后缀以便区分。保存前可发送一个不含工作簿数据的极小请求测试地址、模型和 Key；新增成功后会自动切换到新模型。编辑时空 Key 保留旧值，需要无鉴权连接时可明确清除。独立连接保存在后端配置目录的 `model-connections.json`；损坏的配置文件会明确报错并保留原文件，不会静默覆盖。完整 Key 不会从后端读回，也不会进入聊天记录或浏览器存储。每次请求只携带服务端生成的唯一连接 ID，后端解析到对应连接后再使用实际模型 ID 和该连接自己的 Key 调用。界面显示的模型与请求携带的 modelId 始终来自同一次解析结果；没有任何可用模型时不会发出模型请求，也不会退回规则模式。

Excel/WPS 输入框都有图片按钮。用户可以选择、拖入或直接粘贴
PNG、JPEG、WebP 截图；一次最多 3 张，单张发送前会压缩到 4 MB 以内。图片只随
当前请求及同任务澄清续答发送，图片内容不会写入本地聊天记录；重开后需重新添加。
非视觉模型允许添加/删除附件，但发送前必须切换到真实支持图片的模型，不会静默忽略附件。
环境模型通过 `AI_VISION_MODELS` 声明，独立连接通过“支持图片输入”声明；
SDK 派生连接复用原连接的图片能力，独立 Anthropic SDK 通过
`CLAUDE_AGENT_SDK_SUPPORTS_VISION=true` 显式启用。声明不能使不支持视觉的模型获得视觉能力。
SDK 使用原生 image/base64 消息块并禁用会话转录持久化，不开放文件读取工具。

任务窗格采用持续聊天界面：顶部显示当前工作簿上下文，中间保留消息和计划记录，
底部输入框固定可用。界面统一使用 Office/Fluent 语义字号（12/14/16/20/24px）
和 Segoe UI 中文回退字体。顶部“显示方式”可在标准、加宽任务窗格之间切换，也
可以打开约 90% 的专注窗口查看长对话、结果和工具说明。专注窗口是只读视图，
所有 Excel 写入仍须回到任务窗格预览并确认。旁加载后，Excel 功能区会出现

## 快捷能力

网页“修改前／修改后”对比已移除，侧栏仅保留变更摘要和实际核对状态。WPS 保留原生独立副本并排审阅；Excel 已接原生独立副本链路，能力与宿主限制见上文，不以网页窗口替代。专注对话窗口继续保留。

### 斜杠命令

在输入框输入 `/` 会弹出命令补全菜单：

- `/function <描述>` —— AI 直接生成原生 Excel 公式的短链。输入后先确认写入单元格
  （自动建议数据区右侧第一空列），再结合当前表结构、列头与样本行生成
  「兼容版 · 2016/2019」与「现代版 · 365/2021」两版公式并就地试算，确认后写入目标
  单元格并立即重算，写入前记录撤销快照、可从输入栏「↶ 撤销」。这条链路绕开常规的
  意图确认与规划流程，适合“按行算个占比”“挑出最高错误级”这类单公式需求。模型配置
  里可以为 `/function` 单独指定一个公式模型，默认跟随全局选择。在文件夹模式勾选了
  其他工作簿的工作表时，若描述能对上外部表的列头（如“把 B 表单价按编号匹配过来”），
  会优先在本地确定性地拼出跨表公式（VLOOKUP/XLOOKUP，预填匹配键列与取值列，可改），
  不调用 AI、数据不出本机；这种确定性判断覆盖不了时才走模型生成。模型生成分两级：
  后端先让模型返回结构化函数调用 JSON，由代码编译器拼成公式（语法正确、字面量不
  丢失），失败时自动回退到原有的直接生成公式文本方式；只发送列头、列字母与结构
  摘要，不发原始数据行。工具调用路径只生成一版公式，「兼容版」会带
  「⚠️ 可能不兼容旧版本」警示而非承诺兼容。引用外部工作簿（如 `[B.xlsx]Sheet2!`）
  需在 Excel 中打开才能算出值，未打开时预览卡会提示，写入后打开即自动重算。
  试算未通过或两边都拿不出公式时，会拦截写入并明确提示手动操作，绝不硬写错误
  结果。
- `/model <关键词>` —— 在已配置的模型连接之间切换，输入模型名或描述过滤。

### EB 函数

`=EB(...)` 是一组注册为 Excel Custom Functions 的内置函数，用于处理原生公式表达
不了的特殊文本清理场景：

- `=EB.CLEAN(单元格)` —— 隐形字符清理：清除 CHAR(160)、零宽空格、控制字符与方向
  标记，并把多余空格规整为单个空格；
- `=EB.EMPTY(单元格)` —— 空白检测：识别“看着空但实际不空”的伪空白单元格。

顶部「更多」菜单的「EB 函数说明」打开只读函数参考抽屉。一般计算请用 `/function`
生成原生公式，`=EB(...)` 只保留给正则清理这类特殊场景。

### 文件夹模式

首次产品引导可以提前设置一个常用工作目录，也可以选择“以后再设置”。设置成功后只记住候选目录，不自动授权任何文件；用户仍需在输入框上方的数据范围中逐项勾选工作表。未提前设置时，在数据范围中切换到“工作目录”并点击“选择工作目录”即可。本地服务会递归扫描最多 100 个 `.xlsx`、`.xlsm` 文件，然后按“文件 → 工作表”展示供多选。

- 未指定目标文件的新结果写入所选目录下的 `Excel Bro 结果.xlsx`。
- 如果计划明确修改文件，本地执行器会先判断受支持动作是否真的改变目标状态；同值写入、相同公式写入、已满足的排序及部分清理或格式动作不会替换文件，也不会建立恢复点。确有变化时，先保存全部临时文件，再把既有文件集中备份到所选工作目录的 `.excel-bro-backups/executions/<undo_id>/`，最后原子替换目标；一次执行只建立一个恢复点，多文件按原相对路径保存，不会再把新备份散落在原文件旁。暂时无法可靠判断的动作按“发生变化”处理，优先保证可恢复性。
- 文件夹写入一落盘就登记恢复点，与验收结果解耦；即使显示“验证未通过”，结果卡片仍可撤销。已有文件从本次自动备份恢复，本次新建的结果文件会移除；撤销前会校验写入后的文件指纹，拒绝覆盖执行后新增的人工编辑。
- 数据范围栏提供固定“备份”入口，统一显示当前工作簿内存撤销、文件夹恢复点、状态原因和分类空间占用。可撤销记录支持取出副本、长期保留、逐份删除、打开或复制统一备份路径、清理旧备份和归拢旧版散落备份。管理权限与 Excel 数据范围授权相互独立：接口只接受后端签发的短期 `backupManagementToken`、记录 ID 和受控操作参数，不接受任意磁盘路径。删除确认绑定 manifest 修订号和级联失效列表；服务端先把完整目录原子移入 `.trash`，再同步撤销资格，递归删除被 Windows 占用时显示为待清理而不是虚假成功。取出副本使用稳定 `operationId`，断线重试不会重复复制。“打开文件夹”只打开已登记且已存在的 `.excel-bro-backups`，不会为了展示入口创建空目录。
- 临时锁文件、整个 `.excel-bro-backups` 目录、旧版散落备份和不支持的旧 `.xls` 文件不会参与扫描。
- 扫描结果包含发现文件总数与截断状态；文件夹会话有 30 分钟 TTL 和容量上限。
- 预览后文件内容变化会使来源指纹失效；当前工作簿使用全部授权来源单元格的分块指纹，文件夹计划缺少指纹也会被拒绝，旧计划必须重新生成预览。
- 当前工作簿使用仅在当前加载项会话有效的内存恢复点；失败返回也会携带已捕获快照。直接撤销前会核对工作簿身份、写后区域和本次新建/删除工作表，覆盖不完整或用户后来又编辑时停止覆盖。文件夹模式使用受管理的文件恢复点，目标分为 `restore`（恢复原文件）与 `remove`（移除本次新建文件）。`undo.maxEntries` 只限制最近 5 条快速撤销资格，不直接删除磁盘历史；自动副本至少保留 7 天，1 GB 是软上限，每个原文件最后一份完好副本、主动保留、当前撤销链和异常资料均受保护。磁盘写入另保留 64 MB 安全余量；不足时在替换原文件前停止。

### WPS 表格开发验证

WPS 首期适配以 Windows 个人版 12.1.0.28488 为目标。当前 `apps/wps-addin`
与 Excel EB 共用产品样式和主要交互结构，已接通模型管理、多对话历史、授权范围、
`query_table` 本地确定性统计、固化查询、计划预览、停止和结果表格。WPS 会在每次发送前
重新解析当前工作表，自动跟随模式不会沿用过期授权。
对话中的读取、计算、写前恢复点、逐动作写入和回读核对现在使用与 Excel 相同的
可展开过程时间线，完成后留在历史消息中；用户和助手消息均可复制。WPS 内嵌网页拒绝
现代剪贴板接口时会尝试传统复制接口，仍失败则提示手动选取文字。当前时间线记录的是
WPS 本端实际读取、计算和执行步骤；服务端规划 SSE 的逐事件细节及断点续接尚未接入 WPS。

WPS 开发调试加载项提供受限写入闭环：只允许在本轮明确授权的工作表中写入单元格值、
同形 A1 公式矩阵或清空明确区域内容。服务端生成的普通计划须经服务端校验；本地列映射计划的源值不上传，
改由宿主预检和源、目标状态绑定把关。写入任务的计划通过校验后执行一次，再展示结果供用户审阅，
并保存加载项会话内可撤销恢复点；关闭加载项后尚无持久恢复保证。新恢复点的 v2 指纹区分空字符串与空单元格；旧恢复点发生
歧义时拒绝自动覆盖。预览可查看前 5 行、前 5 列的待写值，也能编辑完整计划 JSON；
编辑后必须重新校验、重新预览和再次确认。公式写入按 `Formula` 而非计算后的 `Value2` 回读；
正式构建仍关闭 WPS 写入，公式动作还需独立实机验收。R1C1 铺满、格式与结构动作、工作目录、任务断点恢复和 EB 自定义函数仍未开放，
界面会明确禁用或拒绝，不会把宿主未实现的能力显示成可用。格式动作在 WPS 侧执行前要过**两道闸**：
执行器的已实现清单（`WPS_SUPPORTED_ACTION_KEYS`）与配置的放行清单（`capabilities.wpsWrite.allowedActions`），
两者缺一即整份计划被拒且不留恢复点；只改一侧不会静默放行。

运行 npm run test:wps 和 npm run build:wps 进行验证；运行 npm run dev:wps
会使用官方 wpsjs debug 在严格端口 3889 启动并登记开发加载项。WPS 子项目的 Vite
开发脚本也统一使用该端口，防止模型请求因任务窗格来源端口不一致而被跨域预检拦截。
首次登记或更新功能区后
需要保存文档并完全退出、重开 WPS 表格。进入独立的“Excel Bro”标签，点击
“打开 Excel Bro”；任务窗格出现后会尝试切回“开始”，不会占用 WPS“开始”标签内的按钮空间。
任务窗格应显示真实工作簿和当前表；“跟随当前”会在发送时重新绑定活动表，也可切换为手动
多表授权。空选择不会自动扩大为当前表或全部表，写入也不会越过同一授权边界。
详细阶段和验收矩阵见适配指导文件。

## Windows 本地安装包

本地安装包用于在一台 Windows 电脑上安装并进行真实 Excel 冒烟测试。它会：

- 把任务窗格和 FastAPI 服务安装到当前用户的本地应用目录；
- 安装仅用于 `localhost` 的 HTTPS 证书；
- 创建只包含加载项清单的 `\\<电脑名>\ExcelBroAddins` 本机共享；
- 把该共享注册为当前用户的 Office 可信加载项目录；
- 登录 Windows 时自动启动只监听本机的服务；
- 注册到 Windows“已安装的应用”以便卸载，并保留用户自行配置的模型连接。

创建和删除本机共享需要 Windows 管理员授权，因此安装和卸载时会各显示一次
UAC 提示。共享只授予当前安装用户读取权限，且不包含工作簿、模型密钥或其他
个人数据。安装包使用标准 Inno Setup 向导，包含欢迎、安装目录、开始菜单、
安装确认、进度和完成页面；安装目录默认是
`%LOCALAPPDATA%\Programs\Excel Bro`，用户可以在向导中修改。Windows“已安装的
应用”和开始菜单中的卸载入口均使用标准卸载器，卸载前会显示确认提示。若删除
共享所需的 UAC 被取消，卸载会中止并保留程序，允许用户重新尝试。个人模型连接
和 API Key 始终保留在 `%LOCALAPPDATA%\Excel Bro`。

构建安装包：

```powershell
npm run build:installer
```

构建机需要安装 Inno Setup 7，并确保 `ISCC.exe` 在 `PATH` 中；也可以通过
`INNO_SETUP_COMPILER` 指定完整路径。PyInstaller 只负责冻结本地服务，外层安装和
卸载生命周期由 Inno Setup 管理。

输出文件为 `dist/Excel-Bro-Setup-0.1.0.exe`。安装器同时注册本机共享加载项目录
和直连注册（等同旁加载），运行后完全关闭并重新打开 Excel，**Excel Bro** 标签会
自动出现在功能区，普通工作簿直接可用，无需手动添加。卸载时会一并移除注册与
共享，但保留 `%LOCALAPPDATA%\Excel Bro` 中的个人模型配置。

该安装方式适合个人单机使用、开发和验收，不需要 Microsoft 365 企业管理员。
组织内正式分发仍应把 Web 应用部署到 HTTPS 服务器，再通过 Microsoft 365
管理中心部署清单或提交 Microsoft Marketplace。

## 安全边界

Excel/WPS 窗格会在空闲时及操作前检查授权目标；检测到文件或授权工作表变化，先提醒选择目标并勾选工作表，确认后才重新读取和预览。旧写入不会自动重放，保存仍需单独确认。详情见 [授权目标前置确认](docs/AUTHORIZED_TARGET_PREFLIGHT_2026-10-05.md)。

- 本地服务默认只监听 `127.0.0.1`。
- 模型只能返回白名单内的 Excel 动作，响应还会经过 Pydantic 和前端双重校验。
- 删除、清空和覆盖动作会在预览中显示风险提示；在已授权任务范围内通过校验后执行，再供用户审阅。
- 不开放 VBA/宏、网络脚本、任意 JavaScript 或外部程序执行。

澄清回答会保留到下一轮；身份暂时无法确认时重新确认范围，再读取并生成预览，不以重新授权冒充写入确认。本地补全规则只在当前窗格内存中保留，不上传、不写入历史；关闭后需重新读取并补充必要规则。修复说明见 [澄清循环修复](docs/CLARIFICATION_LOOP_FIX_2026-10-05.md)。

Excel/WPS 的目标确认位于需求分析之前：已有有效授权与强身份证据时直接分析；目标变化或宿主证据不足时先在独立卡片选择文件及工作表，确认后才读取表头、调用模型和计算。分析后的补全表单只询问缺失规则，不再夹带目标授权。同任务已确认目标且现场未变时不重复确认；写回完成后审阅，确认变更不重复执行。见 [先确认目标，再分析](docs/AUTHORIZATION_BEFORE_ANALYSIS_2026-10-05.md)。


SDK 规划与 Python 结果事件的 2026-10-11 修复/证据边界见 [修复复核记录](docs/SDK_FIX_AUDIT_2026-10-11.md)：写入预览目标在意图阶段绑定；分析结果卡不替代写入计划；双端结果卡只保存引用与结构。更新后需重启 SDK 服务并刷新插件，写入仍须预览确认。

若规划立刻失败，请按实际错误码排查。`TASK_STATE_CORRUPT` 是本地任务账本损坏；需要完整备份后离线恢复，切换模型不能修复。2026-10-12 的双端错误提示修正、本机恢复及真实后端验证见 [WPS 账本恢复记录](docs/WPS_TASK_LEDGER_RECOVERY_2026-10-12.md)。
