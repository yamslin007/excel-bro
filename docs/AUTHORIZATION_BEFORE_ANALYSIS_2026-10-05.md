# 先确认目标，再分析（2026-10-05）

## 问题与交互

原方案在分析之后的本地映射卡里混入目标勾选。用户已经看到了分析结果，却还需要给同一次读取授权；WPS 新包装对象还可能引发提交后的范围恢复提示。授权、业务规则和确认写入必须分开。

2026-10-08 更新：以下是上一版顺序。现先调用无工作簿上下文的消息理解，普通聊天直接结束；只有 `needs_workbook_context` 才进入下述目标检查和授权读取。授权前允许这一消息请求，但字段意图/规划、表头/数据行和写入仍为零。见 [最新顺序与测试](./MESSAGE_FIRST_ROUTING_2026-10-08.md)。

原顺序（历史）：

1. 用户提交需求，先在本机检查当前文件和已授权工作表的元数据及宿主证据。此阶段不读取表头或数据行，不调用意图/规划模型，不显示已开始的需求分析。
2. 已有有效授权且强身份证据一致时直接分析，不重复询问。目标变化或证据不足时先独立选择原目标/当前目标及授权表；没有默认勾选，确认期间仍重新检查。
3. 确认后才读取表头、理解需求并在授权范围内读取计算。遇到实际缺失规则时，业务补全卡只询问该规则，不夹带目标授权。
4. 同一已确认范围内的正常补充和追问不重复确认目标；期间真正换文件/表或出现冲突仍暂停，不能把旧私有规则套到新文件。新源值需重新读取，不能使用旧结果。授权不跨关闭/重载恢复。
5. 生成副本/预览后，由用户另行确认写回。目标同意不会自动执行旧计划或恢复旧写入。

## 实现和边界

- `useAuthorizedTarget.checkForAnalysis` 共享检查状态、目标选择、重复证据比对和仅重试新读取/规划的回调；元数据监听仍用于主动提示变化。
- Office 适配器比对当前文档引用和工作簿 URL；WPS 适配器采集对象引用、路径和授权表身份并检测包装对象是否稳定。仅元数据/尺寸探测，不读单元格值。
- WPS 弱包装证据下的显式同意只保存私有目标键于当前已确认范围的会话内存，不出站/落盘/显示。授权版本在显式确认时推进；普通追问不撤销同意，检测到变化、撤销或关闭/重载才失效。
- 已匹配的授权集合、表身份、真实表头以及前置同意允许重新读取/规划，不构成原生对象相同的证明。写入执行器不消费这个许可，原有强身份/快照/白名单计划/用户确认守卫不变。
- 共享 `LocalMappingResolution` 去掉目标键令牌和目标勾选，保留打开/提交时的现场验证、业务输入和失败重试。历史恢复卡身份不足时需独立目标卡再确认，不把“确认范围”写成业务答案。
- 本批不改模型协议、服务端、环境变量或文件夹执行模式。前端刷新后生效，不要求重启后端。
