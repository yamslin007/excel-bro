用户明确选择了“重新读取并规划”，新计划执行并确认后，旧卡仍显示剩余一个动作。这不是精确续跑验收。

## 已修复

- 重新规划分支原来在 runTurn 返回后无条件读取旧 operation 并恢复旧卡。现在仅在持久发现索引仍属于原 operation 时刷新；新执行登记并保存发现索引后，清理同 task 的旧卡。旧账本不伪造完成，不删除原记录；新执行失败仍保留自己的恢复入口。
- 首次加载的状态查询晚到时，必须核对发现索引仍属于所查询 operation，避免新执行已接管后又恢复旧卡。
- 本机与服务端 JSON 证据改为对象字段无序、数组有序、类型和值严格相等的比较；字段顺序变化不能使合法证据失效。来源、动作顺序、授权、过期和目标检查保留。
- 不再把所有续跑失败吞成 false 后只显示“材料缺失”。恢复卡显示具体拒绝原因；本机记录不存在、精确续跑材料缺失、任务不同、过期及来源证据不同分别提示。
