### B. SDK 自主受控脚本工具

复用 `controlledScript.ts` 的解释器与白名单动作，不新写第二套语法：

- SDK 只能对**用户勾选的多张工作表**生成脚本计划；生成 ≠ 执行。
- 不开放任意 JS、VBA/宏、宿主文件、网络、进程或其他工作簿权限。
- 计划仍走现有校验、来源复核、执行、回读、撤销。
- 关键设计问题：解释器在共享 TS 层，服务端是 Python。要么在客户端执行编译后再提交，
  要么把**同一份**语法/限额/动作白名单做成两端可读的判据；不允许各写一份"看起来一样"
  的解释器。

**验收**：越权脚本（未授权表、文件/网络、原型链）全部拒绝；正常脚本生成的计划与手写
白名单计划走同一条执行链；两端口径一致。

### C. WPS 能力与工作目录

先按 `config/capabilities.json`、执行器与可达入口更新准确差距表，再按优先级实现：

1. 筛选、去重；
2. 工作目录的查询 / 计算 / 执行 / 恢复；
3. 结构与对象能力（行列结构、图表、透视等）。

每组必须同时落实：授权、结果审阅、执行、回读、恢复。不能只放开白名单；不能拿 Excel
的成功代替 WPS 验收；不能把"仅选择 UI 已通"写成"工作目录已接通"。
