# 已选范围与追问授权修复（2026-10-08）

## 源码根因

- Excel 范围面板的「完成」只更新 `selectionConfirmed`/范围 UI，未把新范围提交给 `useAuthorizedTarget` 的授权基线。后续追问仍与旧范围比较。
- WPS 父面板的「确认范围」同样未提交子面板的共享授权守卫；`runTurn` 还会在每条普通新消息开始前清掉弱包装对象的分析同意，导致用户刚确认又被询问。
- 弱证据/暂不可读取被归为 `unavailable`，同名提示却把它描述得像已发现换文件。现在只在确实检测到 `file_changed` 时使用同名不同文件警告。

以上是源码与合成宿主用例证实的缺陷；不能仅凭截图确认真实宿主返回了哪一种身份证据。

## 实现与边界

两端范围确认调用共享 `confirmScope`，重新读取元数据并检查点击时、确认中及最后读取的宿主证据，确认成功才提交已选范围和基线。失败保留已有授权与草稿，不调用模型、读取单元格或写入。它清除旧的重试回调，不自动重放旧任务。

WPS 将确认处理器注册到父范围面板，普通消息不再清除范围同意；显式重新授权的版本推进保持原语义。Excel 范围确认保留用户选择的自动/手动模式，不因目标采纳的默认手动行为改变「跟随当前表」。每条追问仍检查原授权证据、当前目标及重复证据。检测到变化立即撤销旧弱同意，弱证据下切回原文件也需再次确认；关闭/重载不保存这个内存许可。Office 同 URL 下文档上下文替换不能直接沿用原许可。

仅在用户明确提交新的选择时，把旧检查器携带的 `selected` 替换为用户此次选择来核对实时表元数据。普通追问不做这种覆盖，不能扩大授权。目标变化与未知身份仍暂停。业务澄清、源值重新读取、白名单计划、强写入身份/快照、原生审阅副本与写回确认均保留。文件夹模式、模型/服务端协议与 Python 开关未改。

## 双宿主实机待验

1. 刷新/重新打开 EB（前端变更，无需因本次修复重启 Python）。在当前文件选好范围并确认，再发送需求与连续补充；范围未变时不再重复弹目标确认。
2. 勾选但未确认或放弃草稿，不改变已有授权。确认期间删表/切换文件时不得提交陈旧范围。
3. 换到同名异路径文件/真实不同工作表，提交前应先暂停并提醒；未确认前不读取表头/数据行、不发模型请求、不写表。
4. 重开窗格时不能从聊天历史恢复弱同意。确认范围不等于确认写回；副本审阅后仍需独立确认执行。
