# 本地补全与范围确认合并（2026-10-05）

> 历史方案，已被同日的 [先确认目标，再分析](AUTHORIZATION_BEFORE_ANALYSIS_2026-10-05.md) 替代。下文记录当时实现和证据，不是当前交互：业务表单内的目标勾选已移除，必要授权改到分析之前的独立目标卡。

## 根因与修复范围

授权目标前置检查能核对文件和工作表元数据，但 WPS 澄清身份检查还会比较宿主对象引用。宿主每次返回新的 JavaScript 包装对象时，前者通过、后者仍是 `unknown`，于是用户提交本地映射后又收到范围无法确认的提示，被要求再确认一次。这不是澄清卡的时间限制。

本批修复 Excel/WPS 的本地映射、拆分和空白策略补全交互。它替代此前本地补全正常路径中的“先提交答案，再进入独立重新授权卡”；一般语义澄清与历史恢复的严格身份守卫仍保留。

## 新交互

1. 打开补全表单时先检查目标，提交前再次检查。
2. 身份有正面相同证据时，不增加目标勾选，提交后直接重新读取并生成预览。
3. WPS 包装身份不足，但原目标的文件元数据、授权工作表集合和表头仍可核对时，在同一表单显示未勾选的“确认当前操作目标”。用户填写规则、勾选目标，一次提交完成新的范围同意和本地重读，不再追加那两段恢复提示。
4. 目标已变化、文件身份缺失或现场不能读取时，暂停并打开既有目标选择卡；不能把旧补全规则自动转移到另一份文件。目标确认不自动重放操作。
5. 读取期间再次变化时不展示可写计划。源值出现新的缺口时只询问真实的新缺口；补全不重新调用模型。
6. 生成预览不是写入授权；原有白名单计划、快照、执行前强身份检查和用户确认写入不变。

## 安全边界

- `unknown` 没有被改为 `same`。同路径、同名及同表头不是原生工作表生命周期的身份证明；内联勾选是对当前目标的显式新同意，WPS 授权版本递增。
- `wpsClarificationTargetConfirmation.ts` 的目标键只绑定表单勾选；与随机令牌一起仅留在窗格内存，不进入模型请求、聊天历史或服务端恢复账本。界面仅展示文件名与工作表名，不展示完整磁盘路径。
- WPS 本地补全在源读取前后均调用目标守卫；Excel 在生成新预览前重读授权结构并检查当前身份。表单在异步检查中卸载，不再触发后续计算；重复提交有锁。
- 本地源值和补充映射仍不出站、不落历史。真实 fetch 与历史隐私测试先在输入/本地计划证明哨兵存在，再断言请求和历史中不存在。
- 无新增协议或环境变量；文件夹模式和服务端模型不变。CAP-02 未推进；CAP-03 精确续跑未实现状态不变。

## 自动化与限制

覆盖共享表单实际填写/勾选/点击、相同身份不加勾选、提交前换目标清除勾选、读取失败/异步卸载、新包装对象一次提交到新预览、不同路径拒绝、补全期间源值改变、真实 fetch/历史隐私和预览原表写入为零。

三项独立反向变异：移除未勾选禁用、把提交时现场检查替换成缓存、移除 WPS 源读取后目标检查，各自使指定用例失败；均已还原并重新回归。曾误用 WPS workspace 名和中文筛选词，分别导致命令错误与全部跳过，不计作证据；更正后第三项用例实际变红。

未实现：跨关闭私有规则恢复、同路径替换的原生生命周期强身份。仍需在独立测试工作簿实测 WPS 新包装对象行为和 Office.js 检查时序，自动化不替代真宿主验收。
