# 规划手动暂停与检查点继续（2026-10-08）

## 修复原因

WPS 已有预算暂停、断线和刷新后的检查点恢复，但手动停止仅取消接收并结束消息，没有恢复入口。普通继续还误带全局 `modelId`，触发服务端“换模型必须确认”的拒绝；进度适配层丢掉 `sequence`，继续默认使用服务端最新序号，可能漏补断线期间未收到的事件。Excel 的手动停止也没有进入其已有规划恢复卡。

## 双端交互

1. 读取/规划期间点击“暂停任务”：中止当前接收，保留原需求及附件；不自动重发需求。
2. 已有任务身份时保留原 `turnId`，自动核对一次真实状态；查询不发起继续请求，也不能预先声称已经保存检查点。
3. 服务端仍运行或状态读取失败时仅允许再次核对；已完成时接回原结果，不重新规划。
4. 服务端确认可续检查点后，再由用户点击继续。请求沿用原任务及幂等身份，并复核授权；产出仍只进入回答、澄清或待确认预览。
5. 尚未拿到任务身份或服务端无检查点时，如实说明不能精确续跑，保留需求；不伪造恢复能力。明确 404 与暂时无法查询分开处理。

### 停止按钮交互补修（本节覆盖首批手动核对方案）

- 共享过程卡与输入区统一称“暂停”。暂停只是中断客户端接收，不宣称已强制终止服务端处理。
- 原需求留在用户消息/原任务上下文中，不自动回填普通发送框；空输入按 Enter/发送不会创建第二条相同用户消息或再次理解需求。暂停前已输入的新草稿不被清空或旧需求覆盖。
- 自动查询仅一次：有检查点等待用户明确继续；已完成接回原结果且不写入；仍运行或不可查询保留“核对任务状态”；没有检查点明确需要重新开始。无任务身份的消息理解阶段暂停不调用状态接口、不编造检查点，原文本保留在对话中。
- 连续暂停沿用原任务与实际事件游标，自动核对仍不 POST 继续。暂停正在进行的状态核对不触发递归查询；不新增持续轮询、不自动换模型、不改变授权/白名单预览与写入确认。
- WPS 旧操作的收尾不清除新操作的进度；Excel 查询/继续有同步并发闸。新草稿与已提交任务的恢复上下文分开。

本补修仅前端，无新 HTTP 字段或服务端能力，刷新 Excel/WPS 加载项即可。文件夹规划复用 Excel 的既有恢复入口，未新增 WPS 文件夹入口或写入执行暂停。

WPS 普通继续省略模型切换字段，保留任务原模型，不跟随全局模型选择。Excel 既有明确显示的备用模型操作保持原行为；本批不新增 WPS 换模型 UI。

## 状态与安全边界

- 手动暂停是客户端中断接收，不是“服务端已立即暂停”的证明；继续按钮由真实服务端状态决定。SDK 没有可用检查点时不能精确续跑，不能把重新规划包装成继续。
- WPS 初次及续跑进度均传递任务身份、事件序号；游标只记录实际收到的位置。历史补充 `clientLastSequence`，旧历史未知位置从零补收，不采用服务端最新位置冒充收到。
- WPS 同一张卡可再次暂停并核对；重复查询/继续有同步并发闸。新任务/会话使旧查询失效，迟到响应不得接管新任务。
- WPS 暂停前的宿主对象身份仅保留内存；同会话继续/取回结果时核对原工作簿及授权表序号。重载沿用现有授权复核机制，不宣称内存对象身份跨重载保留。私有路径和对象不进入历史或模型请求。
- 本地历史只增加暂停待核对标记、客户端游标和完成标记；未改变 HTTP 协议或服务端能力，没有扩展数据权限。
- 规划恢复不写单元格；写入仍须白名单 `AnalysisPlan`、独立审阅、单独确认。写入执行期间不新增暂停能力。
