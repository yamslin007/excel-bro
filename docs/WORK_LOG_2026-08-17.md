## 阶段 4：集成测试发现 —— 澄清耗尽后兜底选了破坏性操作

### 现象
输入「把数据整理一下」，两轮澄清分别选择「按原话继续」和「我不知道」后，系统自行判定为**按人员列去重**，对 Sheet2 的 B1:C7 生成删除重复行的计划——6 行数据只保留 2 行（阿里、嘟嘟噜）。用户全程未表达过任何删除意图。

### 根因
兜底规则的分支划分不完整。`server/app/intent.py:46-47` 规定：

> 达到上限后，只读查询应采用最合理口径继续并明确假设；写入需求应返回 proceed 交给后续预览，不得直接执行写入。

规则只区分「只读查询」与「写入需求」，**没有区分「需求明确的写入」与「需求依然模糊的写入」**。「我不知道」属于后者，却被按前者处理。

同时 `intent.py:186-191` 是硬约束：`clarificationRound >= MAX_CLARIFICATION_ROUNDS`（配置为 2）时若模型仍返回 clarification，直接判协议违规并强制重试。因此第 3 轮模型被禁止追问，只能 proceed，在零信息条件下自行挑一种解释。

而 `intent.py:51-53` 明确列举「去重 / 删除重复行 / 删除 XX 的行 / 清空 XX 的行」均属写入操作。模型在「整理」的候选语义（去重、排序、格式统一、透视汇总）中，挑中了唯一破坏性的那个；排序与格式化本是非破坏性、更适合作为兜底默认。

### 现有安全网
写入未直接落盘，停在「执行到 Excel」待确认，补充说明也列出了「会删除重复整行、共保留 2 行」。预览机制拦住了这次，但拦截依赖用户读懂补充说明。

### 待改方向（未实施）
1. 兜底规则补一条分支：用户表达「不知道 / 随便 / 按原话继续」时，写入类需求应返回说明性 proceed（如「需求仍不明确，未生成修改动作」），不替用户猜具体动作。
2. 必须猜时偏向非破坏性动作，排序 / 格式化优先于删除类。
3. 可考虑让「我不知道」不消耗澄清额度——该选项本质是用户请求帮助，而非提供信息。

## 阶段 5：集成测试问题修复

基础对话流程中还发现两个前端体验问题，已分别修复并提交。

### 撤销按钮位置

- 问题：撤销按钮同时出现在输入框左下角和执行结果消息下方；消息下方按钮因
  `executedPlanId` 未写入而不显示，输入框按钮在切换对话后仍可能出现，容易误操作。
- 修复：删除输入框中的全局撤销按钮，并在执行成功消息中写入
  `executedPlanId: plan.id`，让上下文撤销按钮只在对应执行结果下方出现。
- 提交：`cfcac69` `refactor: 撤销按钮移至执行结果消息下方`

### 单字符消息

- 问题：基础模式下输入单字符消息，前端未拦截，后端 `prompt` 最小长度校验返回原始
  JSON 错误。
- 修复：`sendMessage` 增加 `text.length < 2` 静默拦截，单字符消息不发送。
- 提交：`1417183` `fix: 拦截单字符消息发送`

## 阶段 6：文件夹模式 UX 改进

工具管理场景测完后转到文件夹模式，发现两个体验问题，一并交给 Codex 修复。

### 缺少批量选择

- 问题：选中多个 Excel 文件后，需要逐个点开每个文件、逐个勾选工作表，文件多时非常繁琐。
  工作簿模式早就有「全选搜索结果 / 清空」，文件夹模式却没有对应入口。
- 修复：`useScopeSelection` 新增 `selectAllSheetsInFile(fileId)` 与
  `clearSheetsInFile(fileId)`，`ScopePopover` 为每个文件渲染「全选本文件 / 清空本文件」
  工具栏。App.tsx 里实际生效的那份内联渲染同步改到位。

### EB 系统表暴露给用户

- 问题：`#EB_RULES` / `#EB_RULES_BACKUP` 出现在可选工作表列表里。这两张表是 EB 规则系统
  早期把规则存进隐藏工作表的遗留物，代码早已不读写，但用户旧文件里会残留，作为数据源
  选项没有意义。
- 修复：`excel.ts` 导出既有的 `isEBSystemSheet`，选择列表渲染前过滤；全选逻辑同样过滤，
  避免系统表从批量入口漏进已选集合；文件过滤后没有可选表时显示「没有可选工作表」。
- 提交：`7054d3e` `feat: 文件夹模式添加全选按钮并过滤系统表`

### 顺带记录的架构事实

改动过程中再次确认：`ScopePopover.tsx` 等抽出的组件目前并未被 App.tsx 引入，真正渲染的
仍是 App.tsx 内联那份。改这类 UI 必须两处同步，否则改了不生效——这与本轮早些时候撤销按钮
「改完全部消失」是同一个坑。P1 组件拆分只完成了一半，接入是遗留工作。
