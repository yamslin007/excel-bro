# WPS 原生并排审阅：侧栏 UI 改造指导

状态：**侧栏改造已实施、自动化通过**；WPS 真机视口（350/430/700 CSS px）与第 0 节的结果疑点**仍待验收**。基于 2026-09-30 的 WPS 真机截图：原表与独立副本已能原生并排，公式试算可见；本文件只处理审阅侧栏的信息层级、按钮布局和可判定的验收口径。原生复制、试算、确认写回的安全约束见 [WPS_NATIVE_SIDE_BY_SIDE_REVIEW_2026-09-30.md](WPS_NATIVE_SIDE_BY_SIDE_REVIEW_2026-09-30.md)。

## 0. 先核对结果，不让 UI 掩盖语义偏差

本次截图中右侧副本的 E4 显示 `p2`；此前用户对同一复合问题类型的确认和真机截图曾显示 `p0`。不能仅凭其中一张截图认定当前错误，也不能把 `p0` 写死进生产代码。先核对**本轮最终确认的规则**、服务端返回的参数化规则、客户端确定性预期、生成公式以及 WPS 副本的公式/计算值回读，弄清是规则已变、组合优先级改变、旧计划残留，还是公式生成/计算出错。如果与本轮确认规则不符，先阻断“确认写回原表”，修复通用的优先级或澄清路径并补回归，再验 UI。测试可使用这一样例，运行时代码不得硬编码业务类别、列字母或等级。

### 0.1 核对结论（2026-09-30 实施时逐段查证）

**链路里没有任何一段会反转或重编号 rank**：

- 服务端 `_rank_entries`（`server/app/excel_agent.py`）只做类型归一，**原样保留**数值。
- `packages/core` 的 `pickHighestRank` 取 rank 最大者；其极性由共享夹具
  `config/column_mapping_cases.json` 的“等级优先级由规则给出：反过来声明则取另一个”
  用例跨语言钉住（`packages/core` 与 `server/app/column_mapping.py` 各跑一遍）。
- `columnMappingFormulaCandidate` **只忠实编码本地 `expected`**：它用每格的实际预期结果
  覆盖该格的 mapping 分支，未知组合才落 `#N/A`。所以公式与副本回读**不可能各自漂移** ——
  它们都等于本地确定性结果。

**推论**：副本 E4 = `p2` 必然来自**下发的 rank**（或一次整格映射命中），不可能在链路后段产生。

**发现并修复的通用缺陷**（不是为这个样例打的补丁）：`valueRank` 的极性只在 schema 描述里
写了“rank 越大越优先”，**没有任何极性示例**，而业务等级命名（名字里最“0”的最严重）与
“数值越大越优先”**方向相反**。模型照抄字面数字不会报任何错，只会让整条链路**一致地**取到
那个**较低**的等级。修法见 §2 补记；运行时代码里没有出现任何业务等级、列字母或具体等级字面量。

**仍无法从仓库判定的事**：本轮对话里用户最终确认的那条规则（映射表与 `valueRank` 的
实际内容）不在代码、夹具或文档中，只存在于该轮的 turn 历史里。**在拿到它的原文或截图之前，
§4 第 5 条不能判为通过**，也不得对外宣称该样例已修复。

## 1. 目标：原生表格负责比较，侧栏负责决策

保持 WPS 的**左侧原表、右侧独立副本**原生并排窗口，右侧只对实际差异坐标做颜色标记；对话任务窗格仍可操作。侧栏不再把大段逐格公式矩阵当作主要审阅画面，也不重新引入窄 HTML 双网格或另开网页对照。审阅卡只回答四个问题：原表是否未写、试算的是哪个副本、改了多少格、现在可以放弃还是确认写回。

建议的侧栏层级：

```text
写入前确认 · 按问题类型填写最高错误级
目标 Sheet1!E2:E6 · 5 格 · 1 个操作

副本已试算并回读  [公式 / 固定值回退，按真实结果显示]
原表尚未写入；右侧独立副本标记 5 处差异。
请在 WPS 并排窗口核对，确认后才写回原表。

查看预计结果 / 查看公式与完整计划（默认收起）
补充说明（仅在必要时展开）

[放弃副本]  [确认写回原表]
```

“预计结果”只可来自可信的本地确定性预期，必须标明**预计、尚未写入**；副本试算后展示的“已回读”必须来自同次试写的真实回读，不得把计划值冒充回读结果。公式与固定值回退要用不同的真实状态文案。若试算或回读失败，不显示“已回读通过”或可写回的主按钮。WPS 没有 Excel 式逐项 `checks`，不得借 UI 伪造验证证据。

## 2. 当前代码中的直接原因与改法

- `apps/wps-addin/src/WpsAgentPanel.tsx` 的 `planCard` 把长说明 `<span>`、`放弃变更`、`保存变更到原表` 一起放进 `.wps-plan-buttons`。`apps/wps-addin/src/styles.css` 为它设置单行 `display:flex`，没有让说明独占一行，也没有阻止按钮被压到逐字换行。这是截图中两个按钮竖排的直接原因。
- 把说明移到独立的状态区域，例如 `.wps-native-review-status`；操作区 `.wps-native-review-actions` 只放按钮。不要靠缩小字号、截断按钮文案或增宽任务窗格掩盖问题。按钮用完整、无歧义的名称：`放弃副本`、`确认写回原表`。这里的“写回”不等于替用户保存 `.xlsx` 到磁盘。
- 约 600–750 CSS px 的任务窗格应显示两枚水平按钮；较窄时两枚按钮纵向**整行**排列。按钮至少 44px 高，文字不逐字断行，正文可换行，长工作簿名允许省略但必须可通过 `title` 或等价方式查看全名。提供键盘焦点与 `disabled`/忙碌态，避免连点触发重复试算、放弃或写回。
- `.wps-plan-values` 当前默认把每个公式直接铺在表格里；`overflow-wrap:anywhere` 让长公式占据多屏高度。计划主卡默认只给目标范围、规模、预计/回读摘要；完整公式放到可展开的“查看公式与完整计划”中，使用等宽字、横向滚动或选中行查看，绝不在窄列里任意折断。默认收起不等于删除信息：授权范围、覆盖风险、未知类别策略和实际写入类型仍须可查。
- 对多 action、编辑计划、取消、错误、放弃与已提交状态也要沿用相同层级。不要只修 `stagedReview` 分支而使其他按钮组再次拥挤。侧栏底部输入框、提示以及 WPS 原生两个子窗口不得被粘性按钮遮挡。

### 2.1 实施补记（2026-09-30）

- `WpsAgentPanel.tsx` 的 `planCard` 已按本节重排：状态说明移入 `.wps-native-review-status`
  （`role="status"`），操作区改名 `.wps-native-review-actions` 且**只含 `<button>`**；
  按钮文案改为「放弃副本」「确认写回原表」。**预览态、编辑态、已试算态三个分支同时迁移**，
  没有只修 `stagedReview`。
- 新增 `.wps-plan-target` 常显目标行（`Sheet1!E2:E6` + `N 格 · M 个操作`）；
  长工作簿名用 `.wps-review-name` 省略并以 `title` 给出全名。
- 逐格内容迁入 `<details class="wps-plan-disclosure">`：**「查看预计结果（尚未写入）」**
  与**「查看公式与完整计划」**默认全部收起；已试算时另加**「查看副本回读结果（已试算）」**。
  默认收起不删信息：assumptions / warnings / 授权范围 / 实际动作类型仍在卡内可查。
- `.wps-plan-values` 改为等宽字 + `white-space: nowrap` + 横向滚动，去掉
  `overflow-wrap: anywhere`（它曾让一条长公式占掉多屏高度）。
- 状态文案由**计划里真实的 `action.type`** 判定：全部为 `writeFormulas` 才说
  “副本已试算公式并回读计算值”，否则说“副本已写入固定值并回读”；未试算时明说
  “尚未生成副本，也未写入原表”，且全卡**不出现**“副本回读”字样。
- 顺带修掉一处**替身比真实现宽容**的缺口：`WpsAgentPanel.test.tsx` 里
  `stageWpsNativeComparison` 的 mock 只返回 3 个字段，缺 `copyAfter`/`originalBefore`/
  `copyFingerprints`/`copyIdentity`。`vi.fn` 的类型很宽松、`tsc` 也放过，但侧栏一旦真的
  用到就会在运行期崩 —— 已补齐全部字段。

## 3. 状态与操作口径

| 状态 | 可见信息与操作 |
| --- | --- |
| 预览，尚未试算 | 目标、预计影响、覆盖警告；“生成右侧副本并排审阅”。不得写“副本已回读”。 |
| 正在生成副本/试算 | 明确忙碌；禁用冲突操作和重复点击。 |
| 副本已试算且回读通过 | 原表未写入、副本身份、实际差异数、公式或固定值回退、并排核对提示；“放弃副本”“确认写回原表”。 |
| 副本结果不符、回读失败或原表变化 | 清楚报错，**不得**显示可继续写回的主按钮；保留必要的恢复或重新预览入口。 |
| 写回进行中/已完成 | 按真实执行与回读结果更新，不以按钮点击代表成功；已完成后不保留可重复确认入口。 |
| 放弃或面板重开 | 清掉待确认入口；副本未能关闭时提示用户手动关闭且不要保存，不能声称已清理。 |

确认写回仍必须走既有白名单 `AnalysisPlan`、原表/副本指纹复核、用户确认、执行器回读及恢复点流程；UI 改造不得扩大已勾选工作表授权，不读取额外数据行，不改服务端协议，不把矩阵写入历史、URL、日志或持久化存储。

## 4. 可判定验收

1. **真机同状态截图**：在宽约 350、430、700 CSS px 的任务窗格各验一次。按钮始终能完整读出、点中且不与状态文案同排争宽；700px 时水平排，窄宽时整行纵排。右侧为 WPS 原生副本，不是 HTML 网格；左侧原表在确认前未变。记录像素宽度，不以浏览器缩放后的物理像素替代。
2. **展开/收起**：默认首屏能看到摘要与操作；长公式默认收起，展开后可读完整文本而不撑破侧栏；关闭后仍可在原生双窗口比较实际计算值。预览值和副本回读值标签明确区分。
3. **交互**：放弃只关闭副本；确认前再核对原表与副本，原表发生变化或副本被改则拒绝写回；忙碌时防重复点击。测试公式试算成功与固定值回退两种实际状态。
4. **自动化**：给 `WpsAgentPanel.test.tsx` 增加可见结构和状态分支断言，防长说明重新回到按钮容器；为关键按钮补可访问名称、禁用态、放弃/确认回调测试。jsdom 不计算真实布局，不能拿 DOM 绿灯冒充按钮未挤压；CSS/浏览器视口检查和 WPS 真机截图必须另报。
5. **结果正确性**：第 0 节的复合值优先级先复核。若本轮确认规则应为 `p0` 而副本是 `p2`，此项为验收失败，不能以 UI 完成结案。

## 5. 交付与回归
