# 给编码助手的执行提示词

以下正文可直接复制。它要求实际实现；本文档本身没有执行其中的开发任务。

---

请在 E:\codex\excel-bro 中实施“贯通 Claude Agent SDK 的实际工作流程”。

目标是让 Excel/WPS 用户在授权范围内发起任务后，SDK 能真实调用本地表格工具，接收有类型反馈，继续查询或修正参数，最后展示真实本地结果或生成可审阅的白名单计划。请落实代码和测试，不停留在分析、文档或工具注册。

先阅读 AGENTS.md、docs/ARCHITECTURE.md、docs/DEVELOPMENT.md、docs/SDK_CAPABILITY_ASSESSMENT_2026-10-09.md、docs/SDK_WORKFLOW_GUIDE_2026-10-09.md，以及隔离 Python 设计和最新结果预览记录。复核当前代码和 git status，保留所有既有未提交改动。历史 SDK_TRANSFORMATION 文档已停用，不照搬其中的代码或工期承诺。

请先给出本轮代码落点和验收安排，然后按下列 A—D 顺序实施；每步通过相关验证后继续下一步。没有需要改变授权边界的事项时，不在每一步结束后重复询问是否继续。环境受限时继续完成独立工作并报告具体阻碍。

一、当前事实，实施前复核

1. run_sdk_plan 当前注册 AGENT_TOOLS_WITH_DATA，实际主要是四个终局工具；默认缺少可工作的数据查询循环。
2. SDK 拒绝非空 dataResults 和 planningReadPolicy != none。两端现有本地查询分支可能携带 dataResults 进入规划。
3. _result 每次独立 sdk.query，只消费最终结果；taskContext 已保留原需求和用户确认。
4. 普通后端已有按宿主裁剪和按需动作 schema；SDK 未复用完整机制。
5. query_table 已有确定性查询与关联协议；Office/WPS 在客户端访问真实宿主，Python MCP handler 不能直接读当前未保存工作簿。
6. Python 产品入口仍关闭；WPS 当前只开放写值、写公式、清空内容。现有原生预览有单表范围限制。

二、本轮实现范围

A. 统一受控工具目录、终局/非终局分发、宿主动作及参数变体裁剪、有类型结果投影。复用现有确定性逻辑，SDK 与普通后端不复制业务规则。核实固定 SDK 版本接口，不盲目升级或假定动态 schema 热更新可用。

B. 实现 SDK handler → 易失任务工具桥 → Excel/WPS 真实读取与 query_table → 已登记回执 → SDK 下一步的异步闭环。一次 query 内可以多轮调用，不要求先接入 CLI 会话持久化。工具桥必须真正被两端产品入口接收，不能只有服务端接口和假回执。

C. 实现本地结果卡，以及结果引用到本地 AnalysisPlan 的预览编译和确认写回。缺少目标时明确询问。跨表来源、一张目标表的预览要正确保留全部来源授权与版本，不通过篡改授权列表绕过单表预览限制。

D. 增加真实工具进度、可识别的失败/预算/取消状态；完成双端一致的交互与验收。文件夹使用已登记文件/表 ID 与现有查询能力，单列 WPS 文件夹入口仍未实现的状态。

新增工具名称按代码确定，可参考 describe_authorized_tables、query_table、submit_local_result、submit_result_plan；保留 submit_plan、submit_clarification、submit_answer、map_column_values。新增工具必须有真实 handler、参数校验、结果投影、授权检查、调用事件和对应测试。工具结果展示与结果计划可新增明确的联合类型分支，不能往旧字段塞未声明的数据。

三、需要落实的工程细节

1. 工具调用由可信上下文绑定任务、宿主实例、工作簿身份、授权版本、operation ID、来源版本和取消代次。查询参数和模型自报 ID 都不构成授权。
2. 结果引用是任务内不透明引用，必须核对登记归属。私有回执凭据不传模型。数据工具先串行；同 ID 同参数重送幂等，同 ID 不同参数拒绝；终局只接纳一次。
3. SDK handler 等待回执时不能阻塞处理回执的事件循环。设置明确等待/累计调用/读取/容量限额，放在 capabilities 配置中。
4. 工具投递与持久进度事件分开；保留回环、Origin/hostId、会话与所有权检查。新旧前后端能力协商失败时明确提示，不降级成原始数据上传或自动切换供应商。
5. taskContext 继续只承载用户语义确认；执行状态使用独立严格类型。取消、撤销、换簿后拒绝迟到回执；断线先查状态，重载丢失易失结果时明确重新读取，不冒充 SDK 精确续跑。
6. 处理原 tool_request/dataResults 分支时，前端就将结果留本地或交由同一桥计算。不能先把矩阵发给服务端，再只在 SDK prompt 中删掉。保留旧数据行请求拒绝守卫，新能力通过新契约接入。
7. 模型回执仅包含经可信登记和投影的状态、引用、允许的结构、固定错误码及必要完整性状态。rows、数值摘要、scannedRows、自由文本 warnings/title/calculation、原始异常和路径不得自动出站。结构字段也要明确校验，不能无差别 JSON 序列化。
8. 结果值默认留本地。模型未见过数值时，不让它编造分析结论；本地结果卡展示真实值。基于上一结果再次查询需显式建模来源链，不把结果句柄冒充 sheetId。
9. 本地编译的值矩阵不进入远端计划校验、模型请求、聊天历史或持久账本。核实旧写入/恢复代码的真实持久化行为，必要时实现有明确边界的会话内执行恢复；不能只复用旧函数而跳过这项检查。
10. 写入必须仍为 AnalysisPlan → 预览 → 用户确认 → 写前复核 → 宿主执行 → 回读。SDK 工具不得直接修改工作簿。

四、明确边界

保持用户选表授权、意图阶段无原始行、精确 MCP 白名单和现有写入确认。保持 SDK 内置 Bash/Read/Write/Edit 等宿主工具关闭，保持 no-session-persistence，保持 pythonExecution.enabled=false。暂不扩 WPS 高级动作，不使用宏、VBA、宿主任意脚本或裸 Python 来补齐能力。

本轮完成不依赖开启 Python或扩大数据出站。实际需要改变约定时，先给出具体缺项、可审查的设计和必要授权范围，继续推进不依赖该变更的工作；不要把所有普通实现选择都变成确认问题。

五、验收必须覆盖

- Excel/WPS 同一合成任务：按明确关联键连接两表、汇总、显示真实结果；需要写入时在明确目标预览，确认前零写入，确认后回读正确。
- 一个任务中至少两次非终局调用；根据一次可修复错误返回修正参数并继续。真正业务歧义走澄清，后答覆盖先答。
- 测试覆盖真实桥、现有查询计算、两端组件点击和实际请求体，不 mock 掉整条核心路径。
- 越权表、跨任务句柄、旧授权、源改变、重复/冲突回执、取消、迟到结果、断线和重载均有行为证据。
- 敏感哨兵出现在本地结果中但不在实际模型消息、回执、持久事件、日志和存储中；覆盖异常/警告通道。
- 普通后端、SDK 图片、直接计划、映射、原有澄清/暂停/恢复回归通过。
- 自动化、真实 SDK/供应商、真实 Excel、真实 WPS 分列。缺少真实环境不能虚报整体完成，也不因此放弃可以完成的实现。

六、测试与交付

运行 npm run test:core、npm run test:addin、npm run build:addin、npm run test:wps、npm run build:wps、项目虚拟环境 python -m pytest server/tests -q、python -m compileall -q server/app。测试临时目录使用独立工作区路径，避免权限问题和运行中开发缓存污染。

同步 TS/Python 协议、README、ARCHITECTURE、DEVELOPMENT、计划表。计划表分别列 Excel/WPS/文件夹已实现、未实现、宿主限制、实机待验和具体证据，不把缺实现写成只差实机。

最终交付：修改文件与职责、真实端到端调用链、测试结果、两端试用步骤、剩余能力及环境限制。只跑假 SDK 的测试时必须明确说明；实际模型调用使用已授权测试连接和合成数据，不接触真实客户工作簿。未经用户要求不提交、推送、发布或打包。
