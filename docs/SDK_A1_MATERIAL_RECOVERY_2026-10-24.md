# A1 恢复材料缺失与过期检查（2026-10-24）

## 本轮修复

Excel executePlan 在 startActionIndex>0 而 undoSnapshot 缺失时，原来会直接续写后缀，把前缀列为成功，但新撤销点只能覆盖后缀。真实执行器 + Office 替身用例复现：期待拒绝却返回执行结果。现在在任何宿主读写之前抛出明确错误，不建立残缺的后缀撤销点。正常初次执行、从第零步开始的恢复不受影响。此修复不声称所有畸形/不完整快照均已覆盖。

三个旧恢复测试曾模拟服务端成功核对后返回 checkpoint=null，新守卫将其正确拦下。夹具现保留生产 reconcileOfficeRangeAction 生成的检查点；已有首步检查点也用生产核对生成，不编造指纹，不放宽续写/写入次数断言。

## WPS 验证

从真实执行器产生两步写入后的本机恢复材料，再分别删除材料或将 createdAt 改为过期。挂载真实面板两次，均只展示需重新规划，不展示继续剩余动作，不自动认领、不调用模型、不产生宿主内容写入。该证据使用替身宿主与网络。

最初的重新规划与材料过期测试只有分段证据。追加验证已串联完整面板链：真实执行器先写两步并中断 → 将生成的本机材料置为过期 → 显式勾选并重新规划 → 新执行身份写入 → 完成回执 → 确认变更 → 卸载并重新挂载窗格。断言登记一次且身份不同于旧执行、动作与完成回执均归新执行、旧动作不补记、确认和重开不增加内容写入、发现索引清空、旧恢复卡不复活。模型返回的新计划仅写第三格，因此该用例实际内容写入仅 Target!A3；不能据此宣称任意重新规划都会跳过前两步，重新规划与精确续跑仍是不同语义。
