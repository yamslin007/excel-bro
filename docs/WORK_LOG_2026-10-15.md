## 任务：双执行方式系统实施与验收

### 背景

用户要求实施两种执行方式，让用户在计划预览卡明确选择：
1. **直接执行到原表**：跳过副本比对，确认后直接写入当前工作簿
2. **先生成副本比对**：生成审阅副本 → 核对 → 写回原表 → 关闭副本

关键要求：
- 两种方式都必须先展示白名单计划、目标范围、变更摘要
- "直接执行"只跳过副本比对，不跳过任何其他安全检查
- 副本比对路径必须只关闭副本，不关闭原表
- 切换执行方式时旧审阅必须失效
- 严格的并发控制和重复提交防护
- 原表始终保持打开，不弹保存询问

### 关键设计决策

#### 1. 直接执行保留所有守卫

**决策**：直接执行只跳过副本比对，不跳过任何其他安全检查。

**理由**：
- 授权边界、计划校验、执行前复核是数据安全的基础
- 恢复快照采集、回读验证、撤销保障是可靠性的基础
- 跳过任何一项都会引入安全或可靠性风险

**验证方式**：
```typescript
// 这个函数是不变式的唯一判据
export function directExecutionStillRuns(): {
  authorizationCheck: true;
  planValidation: true;
  preExecutionRecheck: true;
  recoverySnapshot: true;
  readbackVerification: true;
  undoAvailable: true;
} {
  return { /* all true */ };
}
```

#### 2. 写回身份包含执行方式

**决策**：写回请求的身份验证包含 `mode` 字段。

**理由**：
- 切换到直接执行后，旧副本的"确认写回"按钮必须失效
- 如果身份只包含 `review`、`plan`、`workbookIdentity`，切换后这三项仍然相同
- 加入 `mode` 后，`copy-compare` 的旧回调在 `direct` 模式下被拦截

**实现**：
```typescript
const issued = { review, plan, workbookIdentity, mode: 'copy-compare' };
// 用户切换到 direct
const current = { review, plan, workbookIdentity, mode: 'direct' };
// executionModeTargetChanged(issued, current) → true
// 旧回调被拦截，不会写入
```

#### 3. 副本关闭的三重守卫

**决策**：副本关闭前必须通过身份验证、内容验证、原表验证三重守卫。

**理由**：
- 身份验证：确保关闭的是本次流程创建的那一份副本
- 内容验证：确保副本内容未被人工修改（修改的副本需手动处理）
- 原表验证：确保原表身份仍然匹配（服务端守卫，防止误关原表）

**实现位置**：
- Excel 端：`closeExcelNativeComparison()` + `copyWindow()`
- 服务端：`excel_window_layout.py:close_copy()`
- WPS 端：`discardWpsNativeComparison()` + 身份验证

#### 4. 关闭失败不改变业务结论

**决策**：副本关闭失败单独提示，不影响原表执行结果和撤销功能。

**理由**：
- 副本关闭是收尾操作，不是业务操作
- 原表写回成功 + 回读验证通过 = 业务成功
- 副本关闭失败只需提示用户手动关闭，不能把"写回成功"改成"失败"

**实现**：
```typescript
// 写回成功后
const copyCloseResult = await closeExcelNativeComparison(session);
if (copyCloseResult !== "closed" && copyCloseResult !== "already_closed") {
  // 只是提示，不改变 outcome: "verified"
  setFeedback({ text: "副本关闭失败，请手动关闭。原表写回成功，可撤销。" });
}
```
