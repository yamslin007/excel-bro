# 公式恢复验收在首写前取消：修复记录

## 复现与边界

用户现场为三张结果表各写一个跨表公式，探针在首写前以通用“未登记可恢复”错误取消。截图不能单独证明哪个资格条件失败。本轮自动化复现了其中一个真实缺口：模型未调用工具读取时，Excel 的 `officeRecoverySupport` 在本机公式来源采集之前就因缺少可信来源名单而拒绝登记。原组件用例预设了工具读取，未覆盖这条路径。本轮未对用户真实账本或工作簿作写操作，也不声称已取到该轮原始计划。

## 修复

- 新增 `prepareFormulaSourceEvidence`：仅对首次执行的纯公式计划，用共享公式判据解析静态跨表依赖；授权检查后实际读取宿主来源摘要，成功后才登记来源名单与指纹。读取前后复核身份、授权、会话和来源模式。没有读取成功就没有来源证明。
- 不改混合/固定值计划的规划证据；不接入续跑采集，旧执行仍对照原基线。同表、动态、外部、来源同时为目标等不支持恢复的边界保持原样。
- 共享 `bindRecoveryProbe` 保持消费一次 arm、零写入取消，分开报告身份、恢复资格、数量、重复目标和矩阵形状；Excel 传递具体拒绝原因。`RecoveryProbeCancelledError` 在审阅层映射成 `ReviewNotStartedError`，显示“未执行”而非“需要核对”。
- 两处旧提示（产品身份与意图阶段）统一为授权校验后执行一次、回读供审阅，取消“写前另行确认”。不增加执行前按钮。
- WPS 沿用现有宿主来源覆盖采集与材料恢复，仅共享探针诊断变化；文件夹模式不使用该 Office.js 适配逻辑。无协议字段变化。

## 验证

- 真实 App + 执行器 + 替身宿主：模型有/无工具读取两种三公式计划均登记一次，只写前两格，第三格留空；第 2 步回读后中断，完成回执只有 `[0]`，来源未写。另测同表资格拒绝时零写入、零登记、显示具体原因和“未执行”。
- 本机来源助手：读取后才记账、越权不读、读取失败不记账、异步授权变化不记账、混合计划不替换原证据。
- Excel 全量 **1624 passed / 9 skipped**；WPS **1245 passed / 8 skipped**；core **969 passed**。
- 三端 `tsc --noEmit` 均退出 0；两端构建与服务端 `compileall` 退出 0；定向 ESLint 为 0 error / App.tsx 8 条 hooks warning；修改文件 `git diff --check` 通过。
- 服务端 **1945 passed / 28 skipped / 2 failed**。失败均为 `test_python_event_delivery.py` 返回 `unavailable`；`docker info` 确认 `dockerDesktopLinuxEngine` 管道不存在。未改测试规避。初次定向测试因系统 pytest 临时目录权限报错，之后全量使用独立测试目录完成。

全部日志位于 `outputs/formula-probe-fix-20261030/`（目录建立时尚未跨日）。自动化不等于真机已验收；A1-GATE 不据此整体通过，A2 未启动。

## 当前现场如何继续

刷新 Excel 窗格；重启后端使提示更新生效。保留原夹具与四表授权，重新启用“下一次第二步中断”（上次失败已消费 arm），再发原任务。不需要手点“执行到 Excel”。预期结果1/结果2的 B2 已是公式，结果3的 B2 仍空，恢复入口为“核对在途动作”。本轮未替用户执行这次真机写入。
