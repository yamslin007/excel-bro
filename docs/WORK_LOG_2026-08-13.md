# Excel Bro - 2026-08-13 工作记录

## 🎯 主题：执行后撤销机制补全 —— 修复删除撤销乱序 + 拆分表支持撤销

延续「执行工具后都有撤销」的收口方向（能 Ctrl+Z 完成的不用自带撤销，结构类操作必须可回退），今天把撤销从「只覆盖单元格写入」补成「结构操作也可完整回退」，并把撤销入口放到执行结果消息卡片上。

---

## 阶段 1：修复「删除后撤销数据对不上」（位置塌缩 bug）

### 现象
多次执行后，执行「删除工作表」再撤销，撤销后的工作表顺序/数据与执行前对不上。

### 根因
`captureDeletedWorksheet` 在**删除那一刻**读取 `sheet.position`。顺序删除 22 张表时，每删一张剩余表的 position 就收缩，最终 22 份快照的 position 全部塌缩成 1（或很小值），撤销按错乱顺序叠加恢复 → 顺序/数据错乱。

### 修复（`src/excel.ts`）
- `executePlan` 起始改为 `worksheets.load("items/name,items/position")`，sync 后构建 `positionByName` 原始位置映射。
- `captureDeletedWorksheet(context, sheetName, originalPosition?)` 快照改用 `originalPosition ?? sheet.position`，记录执行前原始位置。
- `undoExecution` 对被删表按 position **升序**逐个恢复：每个被删表前面的残留表 + 已恢复表数量始终 ≥ 其原始位置，因此直接赋回位置不会越界，无需加载 count 或夹紧。

## 阶段 2：拆分表（splitGroupAggregate）支持撤销

### 根因
拆分完全不产生撤销数据：`recoverableActionRange` 无 split 分支（不捕获单元格）；`executePlan` 只跟踪 `createWorksheet` 动作新建的表 → 拆分新建的 N 张输出表全没被跟踪；`undoSnapshot` 为 null → 连撤销按钮都不出现。

### 修复（`src/excel.ts` + `src/App.tsx`）
- `executeAction` 签名扩展为 `executeAction(context, action, actionIndex, collector)`，新增 `ActionUndoCollector { createdWorksheets, overwrittenRanges }`。
- 拆分分支登记撤销数据：
  - 每张新建输出表 → `collector.createdWorksheets`，撤销时删除。
  - replace 策略覆盖已有表 → 覆盖前把原占用区（公式/数字格式/填充/字体）拍进 `overwrittenRanges`，撤销时写回。
  - 空表被覆盖 → 追加「清空写入区」快照，保证写入区超出原占用区的单元格撤销后也清空。
- `executePlan` 把 collector 数据并入 `undoSnapshot` → 拆分后出现撤销按钮。
- 撤销回放顺序：`undoExecution` 逆序回放 ranges，先清空写入区、再恢复原占用区，重叠处以恢复为准。
- 撤销消息区分「移除了本次执行新建的工作表」/「恢复了被删除的工作表」。
- `invalidateStructureCacheForActions` 把 splitGroupAggregate 视为结构操作，执行后强制失效结构缓存。

## 阶段 3：撤销入口移到执行结果消息卡片

### 背景
撤销按钮原先藏在输入框左下角（图片按钮旁边），不显眼，用户此前未注意到。

### 改动
- `ChatMessage` 增加 `executedPlanId`，执行结果消息记录对应计划 id。
- `MessageItem` 在「验证通过/未通过」卡片下显示「↶ 撤销本次执行」，仅当该消息的 `executedPlanId` 与 `lastUndoSnapshot.planId` 匹配（即最近一次执行）时出现，附注「只保留最近一次执行的撤销数据」。
- `styles.css` 新增 `.undo-row` / `.undo-row-hint`。
- 输入框左下角的快捷撤销入口保留，两处共用同一份快照。
