# Excel Bro：WPS 个人版适配指导方案

- 文档版本：v0.1
- 日期：2026-09-22
- 状态：实施中；W0 核心加载、W1 基础授权读取和 W2 只读 Agent 核心闭环已在目标个人版通过。
- 首个目标环境：Windows，WPS 表格个人版 12.1.0.28488。
- 实施对象：现有 Excel Bro 项目。
- 依据：当前仓库代码、[项目架构](ARCHITECTURE.md)、[开发约定](DEVELOPMENT.md)及各节引用的 WPS 官方资料。
- 阶段使用 W0～W4 命名，与项目既有任务恢复阶段 A/B/C 区分。

## 1. 目标与推荐路线

让用户在 WPS 表格中打开 Excel Bro 侧边栏，使用现有对话、模型管理、工作表选择和受控工具能力。

推荐路线是：增加 WPS 加载入口和宿主适配层，复用现有 React 界面、FastAPI 服务、模型规划协议与确定性计算逻辑。Excel 与 WPS 使用各自的工作簿 API；文件夹模式继续由后端处理磁盘文件。

首期交付范围为“在目标个人版中可靠加载，并对明确授权的工作表进行只读查询”。写入需要另外完成预览、验证、撤销和失败处理；断点恢复需要进一步验证执行现场，不能随普通写入一起默认开放。

个人版作为第一验收环境。版本号、发行渠道、加载项能力和实际运行结果共同决定支持范围，不以“个人版/企业版”名称推断全部能力相同，也不提前要求用户更换企业版。

## 2. 当前证据与尚未确认的事项

| 项目 | 已知情况 | 对实施的影响 |
| --- | --- | --- |
| 目标版本 | 用户截图显示 WPS 表格 12.1.0.28488；本机运行路径与该版本一致 | 先在该版本实测，不能将结果泛化为所有 WPS |
| 本机安装组件 | 已观察到 jsetapi、jsapiservice 等相关组件 | 只能说明组件存在，不能证明第三方加载项已获准加载 |
| 加载项注册 | 已通过官方开发登记在目标个人版显示功能区和任务窗格 | 正式用户安装、停用和升级流程仍待实现 |
| 官方部署方式 | 官方推荐 publish 模式；旧 jsplugins.xml 模式从 12.1.0.16910 起受限 | 目标版本需要先验证官方发布通道，不沿用旧配置教程 |
| 个人版可用性 | 官方可用性说明要求安装包包含加载项功能；部分部署资料的版本列表主要描述企业版 | 现有资料不足以确认这个个人版的完整可用性，W0 是必要前提 |
| 工作簿读写 API | 官方提供表格 JSAPI、任务窗格与 Range 数据接口 | 每个实际使用的接口都要在目标版本验证 |
| 网页运行环境 | 任务窗格已在目标个人版完成宿主读取、后端请求和只读 Agent 核心闭环 | 取消、断网、来源切换等故障场景继续列入发布前回归 |
| 写入与恢复 | 仓库已有 Office.js 和文件夹执行/恢复实现 | 不等于已有 WPS 在线工作簿执行或恢复能力 |

部署约束依据 [WPS 加载项开发说明](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/wps-integration-mode/wps-addin-development/wps-addin-development-instructions)。个人版支持边界还需结合[加载项可用性说明](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/addin-api/wps-addin-availability)与实测确认。

## 3. 现有代码需要适配的地方

| 位置 | 当前职责/依赖 | 适配要求 |
| --- | --- | --- |
| apps/excel-addin/index.html、src/main.tsx | 加载 Office.js、初始化前端及公式相关模块 | WPS 使用独立入口，避免加载即执行 Office 专属初始化 |
| apps/excel-addin/manifest.xml | Office 功能区、任务窗格、SharedRuntime、自定义函数注册 | 不能直接当成 WPS 加载项配置 |
| apps/excel-addin/src/App.tsx | 实际包含初始化、工作簿扫描、查询路由、执行入口和恢复接线 | 必须逐个改造真实调用点；不能只新增一个未接入的适配模块 |
| apps/excel-addin/src/hooks/useWorkbookContext.ts | 也包含 Office 初始化和结构读取逻辑 | 先核对实际调用关系，避免只改 Hook 而遗漏 App.tsx 的内联流程 |
| apps/excel-addin/src/excel.ts | Office.js 读取、执行、验证、撤销、指纹及恢复 | 保留 Office 实现，逐项定义 WPS 对应能力 |
| apps/excel-addin/src/dataTools.ts | 确定性查询、分块读取与 Office API 调用 | 分离宿主读取与可复用计算，不能复制整套业务统计代码 |
| apps/excel-addin/src/cellNormalization.ts、tableSchema.ts | 单元格标准化、表头识别 | 复用共同规则，增加 WPS 返回类型的输入归一化 |
| apps/excel-addin/src/deterministicTools.ts | 固化查询执行 | 注入当前宿主读取器，并重新核对当前授权与来源身份 |
| apps/excel-addin/src/contracts.ts、server/app/models.py | 前后端协议 | 新增宿主或能力字段时同步修改，两端兼容旧请求 |
| server/app/folder_workbooks.py | 文件夹中的磁盘工作簿执行与备份 | 保持独立；不能用于替代 WPS 打开工作簿的实时读写 |
| config/capabilities.json | 项目限额 | WPS 分块大小、轮询及工作量限制集中配置，实测后定值 |
| packaging/ | 当前安装、运行时与 Office 注册 | WPS 增加独立注册流程，不覆盖 Office 配置 |

当前 App.tsx 多处以 isRunningInExcel()、Office.onReady 或直接 Excel.run 判断流程。不能把 isRunningInExcel() 简单改成“Excel 或 WPS 都返回 true”，否则后续仍会调用不存在的 Office API，甚至放开不支持的执行入口。

当前还存在“非 Excel 环境使用演示数据”的路径。真正的 WPS 环境初始化失败时必须显示可诊断错误，不能悄悄展示演示工作簿并让用户误以为读取成功。

## 4. 宿主适配架构

建议形成以下职责关系：

| 层 | 复用内容 | 宿主差异 |
| --- | --- | --- |
| 界面和业务协调 | 对话、主题、模型设置、范围选择、进度时间线 | 初始化、宿主能力提示、菜单及窗格控制 |
| 确定性工具 | 字段识别、条件匹配、分组、计数、统计 | 原始单元格数据的读取方式 |
| 宿主适配层 | 统一的业务输入/输出 | Office.js 适配器、WPS JSAPI 适配器 |
| 服务端 | 模型连接、意图分析、规划、任务账本 | 根据任务宿主和能力约束规划及恢复资格 |
| 文件夹模式 | openpyxl 等现有磁盘处理通道 | 与当前打开工作簿的宿主分开判断 |
| 安装集成 | 本地服务、前端资源、模型配置 | Excel 注册与 WPS 发布/启用分别处理 |

适配层至少覆盖：宿主检测、就绪等待、工作簿身份、工作表元数据、授权范围读取、数据标准化、变更通知和能力查询。写入、验证、撤销、恢复接口在后续阶段按白名单开放。

WPS 应探测实际注入的宿主对象，并以官方 SDK/当前模板验证可用访问方式；不要假造 Office 全局对象，也不要用某个全局对象是否存在作为全部功能可用的证明。

首轮只抽取支撑只读闭环所必需的接口，保留现有 Office 执行实现。避免把整个 excel.ts 一次性重构后才开始验证 WPS 能否加载。

### 4.1 能力必须分开表达

至少区分：

- 能否读取工作簿结构、授权范围数据及当前选区。
- 能否订阅数据变化、是否具备可靠工作簿身份。
- 支持哪些 AnalysisPlan 动作。
- 支持哪些动作的独立验收、撤销和断点恢复。
- 是否支持 EB() 自定义函数、公式试算及特定界面能力。

普通写入、独立验收、撤销、恢复是不同能力，不用一个 supportsWps 或 canWrite 标志全部放行。

能力应进入规划约束，并由本地执行入口再次校验。模型提示词和隐藏按钮都不能替代执行层校验。未知宿主及未知能力默认不可执行；旧客户端的兼容策略只维持原有通道，不据此开启 WPS 写入。

### 4.2 三类来源保持明确

“当前 Excel 工作簿”“当前 WPS 工作簿”“工作目录中的磁盘文件”是不同数据来源。共享 UI 不意味着可以自动切换来源。

WPS 用户打开的文件可能有未保存修改。直接让后端读取同名磁盘文件会得到旧数据；通过 openpyxl 保存该文件也不能更新 WPS 内存状态，还可能导致覆盖。因此不得把这种路径作为宿主 API 缺失时的透明降级。

## 5. W0：先验证目标个人版的接入能力

目标：得到可复核的“可接入/存在阻碍”结论。

实施前准备独立测试工作簿和最小加载项验证页，记录 WPS 完整版本、发行渠道、系统信息与测试配置。验证页不需要接入模型，也不修改现有工作簿。

验证顺序：

1. 按当前官方 WPS 表格模板确认加载资源结构和 Ribbon 回调方式。
2. 使用官方 publish/启用流程验证个人版能否安装本地测试加载项。
3. 在 WPS 表格功能区看到入口，点击后创建或显示任务窗格。
4. 重复点击复用窗格，不持续创建多个窗格；关闭再打开仍能工作。
5. 确认实际宿主对象，读取测试工作簿名、工作表名称及一个已授权单元格。
6. 验证前端资源、本地服务健康检查、普通请求、流式响应和取消能力。
7. 完全退出并重启 WPS 后再次确认加载；测试停用及重新启用。
8. 在没有开发调试配置的环境复测用户安装路径，区分“调试成功”和“可交付安装成功”。

输出一份接入验证记录：每项结果、必要截图、脱敏错误与具体限制。此前检查过组件 DLL、官方文档或 npm 模板不能代替上述结果。

如果官方通道在此个人版中被限制，先记录限制来源、错误与官方支持路径，再决定后续路线。不得用覆盖 WPS 安装配置、降低安全设置或绕过许可限制来宣布适配完成。

**通过条件：目标个人版可经受支持的安装/启用路径加载，窗格能读取真实测试工作簿，并且用户安装路径可复现。未通过前不扩大到完整读写适配。**

## 6. W1：工作簿读取与授权范围

目标：侧边栏能够准确展示当前 WPS 来源，并且只读取用户授权的数据。

### 6.1 工作簿和工作表身份

不能只用显示名称识别来源。同名工作簿、另存为、重命名、多个 WPS 窗口都可能导致误绑定。

POC 要验证工作簿路径或稳定标识、工作表标识的可用性与生命周期。未保存工作簿只能使用当前会话身份，不宣称可跨重启恢复。若工作表没有可靠稳定 ID，则通过原始身份与结构复核保守判断，无法确认时要求用户重新选择。

任务发起时绑定宿主、工作簿身份和授权工作表。等待模型或分块读取期间切换活动工作簿，不能让后续数据块读入另一本工作簿。

### 6.2 授权规则

- “跟随当前”在提交任务时确定工作表，执行中的任务不随用户切换而改变。
- 固定选择模式只读取被勾选表；显式空选择不能降级成活动表或全部表。
- 显示候选工作表名称等必要元数据与读取数据行分开处理；未勾选表不进入字段/数据读取。
- 工作表被删除、重命名或身份失效时停止原任务并提示重新选择。
- 固化查询、历史消息上的重试/继续入口也必须核对当前来源和授权，不能把工具保存的旧表名当成当前授权。
- 意图阶段仍只向模型发送受控结构信息，不发送原始数据行。

### 6.3 数据标准化与分块读取

WPS Range 接口与 Office.js 返回结构不同，需要先转成现有计算工具能接受的标准矩阵。验证单个值、一行、一列、二维区域、空区域及非 A1 起始区域。

读取测试至少覆盖：文本、数值、布尔值、空值、错误值、公式结果、数字格式、前导零编码、日期和合并单元格。日期系统与格式化文本要单独核对；不能把所有数字误认成日期，也不能因数值化丢失编码。

官方区分 [Value2](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Range/member/Value2) 与 [Text](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Range/member/Text)。实现需实测多单元格的返回形状及混合格式，不能假设 Text 总是完整二维矩阵。

分块读取必须保留第一次识别出的表头，后续数据块不能把第一条记录再次当作表头丢掉。取消、关闭工作簿和权限失效在块边界检查。

WPS 同步桥接的性能需要实测。分块大小和总工作量限额放入 capabilities.json；先用测试结果确定，不直接照搬 Office 的批次参数。

用户在读取中修改数据可能得到混合时间点的结果。根据可用事件、任务代次及前后指纹检查一致性；无法证明一致时提示重试，不把普通分块读取宣称为事务快照。

### 6.4 变更和缓存

优先验证宿主变更事件。事件不可用时可使用有限轮询辅助更新元数据，但只轮询表名和尺寸无法发现同一区域的内容修改。

数据失效机制未验证前，对 WPS 关闭跨任务查询结果复用。缓存启用后必须绑定宿主、工作簿身份、授权范围与可靠的数据版本或指纹。

**通过条件：结构和数据读取得到正确结果；空授权、来源切换、表名冲突、跨块边界及格式问题均有验证。**

## 7. W2：接入只读 Agent 和统一 UI

目标：形成“提出问题 → 读取授权数据 → 本地计算 → 在对话中回答”的完整闭环。

复用现有意图判断和确定性查询能力，WPS 适配器提供数据。超过模型快照容量的数据由本地工具读取完整授权区域，不能用前 200 行近似回答完整统计。

本阶段能力范围：

| 功能 | 处理方式 |
| --- | --- |
| 模型添加、连接测试、管理 | 复用现有本地服务；验证实际窗格网络能力 |
| 当前表、选择多表、范围提示 | 使用 WPS 实时结构和相同交互规范 |
| 条件计数、分组统计、查找等只读任务 | 本地计算后返回对话答案 |
| 固化查询 | 读取器适配、重新授权和来源校验通过后开放 |
| 进度、停止、错误诊断 | 复用统一事件协议与时间线；保留真实工具和动作信息 |
| 生成或执行写入计划 | 暂不提供可执行入口，明确当前宿主支持范围 |
| 公式试算、EB() 注册 | 暂不开放；现有公式预览可能临时写入单元格 |
| 历史写入计划、撤销、恢复 | 统一入口拦截，不因旧记录存在而开放 |

WPS 首期如尚未完成文件夹模式验收，应禁用其写入及恢复入口；如另行开放，必须明确显示磁盘来源、重新确认授权并完成文件占用与格式验收，不能作为在线写入的后备通道。

只读限制应覆盖正常操作、历史卡片、固化工具、快捷命令、失败重试和恢复入口。模型即使返回 AnalysisPlan，也不能在 WPS 首期执行。

界面继续使用已有主题变量、按钮尺寸、卡片布局和默认展开时间线。WPS 窗格宽度、打开关闭、窗口切换与 Office 的宿主控制不同，需单独验证；状态提示不能依赖 Office 对话框。

用户关闭窗格或连接中断时，不把失联显示成“已完成”或“已取消”。后台任务状态和前端连接状态分开显示。

**通过条件：只读问题始终在对话中给出完整数据结果，全部写入入口受控，Excel 现有行为无回归。**

## 8. W3：按动作开放写入、验证与撤销

W2 完成后再实施。本阶段继续遵守白名单 AnalysisPlan、预览、用户确认、确定性执行和独立验收流程。

先选择能完整保存写前状态、确定性比较写后结果的简单范围动作。拆表、删除表、图表、透视表等结构或复杂对象动作后续逐个开放。

每个动作都必须填写能力验收记录：

| 验收项 | 必须回答的问题 |
| --- | --- |
| 预检 | 当前版本、来源身份、授权范围和目标是否满足条件？ |
| 预览 | 是否准确说明目标、实际影响和必要风险？ |
| 执行 | 是否只调用白名单 API，批次失败是否可定位？ |
| 验证 | 是否重新读取真实结果，核对值、公式或属性？ |
| 撤销 | 是否有足够且完整的写前资料，能否检测后续人工修改？ |
| 异常 | 是否准确区分已完成、失败、未执行和结果不确定？ |

验证未通过不意味着没有写入；保留已有恢复资料和对应入口，不能重现“数据已改，但验证失败后无法撤销”的问题。

恢复资料不足的动作应在确认前说明并阻止不满足产品恢复要求的执行。不能默认把同名磁盘副本视为 WPS 当前内存状态的备份，也不能擅自保存用户尚未保存的工作簿。

已有文件夹备份继续放在已登记工作目录的 .excel-bro-backups，复用受管清单、指纹、原子更新、保留和清理规则。WPS 在线撤销采用何种快照/副本方式必须根据宿主 API 的覆盖能力决定。

不支持的动作明确拒绝；不得偷偷改用宏、任意脚本、COM 外部控制或 openpyxl 改写当前打开的文件。

## 9. W4：任务恢复、复杂动作与自定义函数

### 9.1 恢复必须绑定宿主现场

参考 [任务断点恢复指导](TASK_CHECKPOINT_RECOVERY_GUIDE.md) 和 [模型切换续跑修复指导](PLANNING_MODEL_SWITCH_RESUME_FIX_GUIDE.md)。

现有规划账本和模型切换机制可以复用，但需要验证 WPS 来源身份、授权、工具产物和数据指纹。不能因为模型切换成功，就认为工作簿执行现场可恢复。

对于有副作用的动作：

- 保存稳定 operationId、计划版本、原始授权、宿主/工作簿身份及 checkpoint。
- 写入前持久保存目标写前状态，写入后读取结果并保存完成记录。
- 异常恢复时比较实际状态：等于写后则补记完成；等于写前才允许重试；其余状态挂起核对。
- 继续使用同一任务和时间线，跳过已核验完成动作，不能把用户“继续”当成全新写入请求。
- 跨宿主打开同一文件不自动转移执行权；Excel 的恢复入口不能直接交给 WPS 执行。
- 任一动作普通执行可用，并不自动获得恢复资格。

现有同源 localStorage 或历史记录可能被两个宿主访问。必须隔离活动任务发现索引或增加归属过滤，避免 WPS 展示可执行的 Office 恢复操作；共享模型配置和可读历史可以独立保留。

### 9.2 自定义函数另行适配

EB() 当前依赖 Office 自定义函数及共享运行时。WPS 有自己的[自定义函数机制](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/wps-integration-mode/wps-addin-development/wps-addin-custome-function)，需要验证注册、异步结果、重算、错误显示和保存后重开行为。

WPS 能打开侧边栏或执行普通范围写入，并不能证明 EB() 可用。本项独立验收、独立开放。

## 10. 发布、安装与本地服务

### 10.1 部署选择

优先采用 WPS 官方推荐的 publish 流程，使用表格组件类型 et。开发调试注册与正式启用流程分别记录。

当前官方说明和模板存在不同年代的入口描述。实施时固定验证过的工具版本，使用该模板的资源约定；WPS Ribbon 加载根与业务任务窗格页面分开组织，避免与现有 Office index.html 的入口职责冲突。

官方 [TaskPane 说明](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/addin-api/TaskPane/task-pane-overview)及[创建任务窗格接口](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/addin-api/Application/member/CreateTaskpane)可用于验证窗格生命周期。部署/启用集成参考[业务系统集成说明](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/wps-integration-mode/wps-addin-development/wps-addin-integration-business-system-development)。

### 10.2 用户安装流程

W0 通过后再决定是否集成现有 Windows 安装包。推荐交付流程：

1. 安装或复用 Excel Bro 本地运行时。
2. 检测目标 WPS 和加载项能力，显示实际检测结果。
3. 引导完成官方加载项启用；需要用户操作时，明确说明当前步骤。
4. 检查注册、前端资源和本地服务状态。
5. 如需重启 WPS，提醒用户保存工作；不强制终止打开的文档。
6. 用户在“开始”标签最右侧的 Excel Bro 分组打开侧栏，并选择授权工作表。

安装成功、加载项启用成功和功能区已显示是三个不同结果。检测未证实前不能提示“已经全部就绪”。

升级保留模型配置、用户工作目录与其他加载项。卸载只移除本插件登记的资源；不能覆盖整个 WPS 加载项清单，也不能误删 Excel 端仍使用的共享运行时。

### 10.3 服务与网络

目前开发前端使用 https://localhost:3000，本地后端使用 http://127.0.0.1:8765。WPS 需验证证书、页面来源、混合内容策略、流式读取及取消；生产包还需测试实际静态资源服务，不能只以 Vite 调试成功为依据。

继续限制监听和允许来源，不因连接失败直接扩大到任意来源或局域网。诊断不记录模型密钥、原始表格数据或完整敏感路径。

Excel 与 WPS 同时运行时应复用本地服务。启动程序先确认端口对应服务及版本，不能按端口号直接结束未知进程；关闭一个宿主也不能停止另一个宿主仍在使用的服务。

## 11. 格式和兼容范围

首期以本地 .xlsx 工作簿为验收格式。未保存工作簿可以单独验证会话内读取，但不开放依赖磁盘身份的恢复。

.xls、.xlsm、.et、加密文件、云文档、协作编辑和特殊对象分别记录支持状态，不继承 .xlsx 的结论。后续如支持写入，需要验证保存后格式、公式、样式和对象是否保持。

WPS、Excel 与后端对公式计算、日期系统和复杂对象的处理可能不同。遇到差异应限制能力并解释具体影响，不能把“文件能打开”作为完整兼容的标准。

## 12. 测试与验收矩阵

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| W-01 | 指定个人版官方启用、重启、停用 | 用户安装路径可复现，重启后入口符合预期 |
| W-02 | 重复打开窗格、关闭重开、多窗口切换 | 不重复创建失控窗格，不串工作簿 |
| W-03 | 空选择、当前表、固定多表、未授权表 | 授权不扩大，显式空选择停止数据读取 |
| W-04 | 同名工作簿、另存为、未保存、表重命名/删除 | 来源身份可核对；无法确认时安全停止 |
| W-05 | 单值、单行、单列、二维区域、非 A1 表头 | 标准化和表头定位正确 |
| W-06 | 超过 200 行、超过一个读取块、尾块 | 完整计数准确，无漏行或重复行 |
| W-07 | 日期、编码前导零、公式、空值和错误值 | 与已知样本的预期结果一致 |
| W-08 | 等待模型或读取中切换/修改/关闭工作簿 | 不混用来源；变化能失效、重试或明确中止 |
| W-09 | 只读统计、新对话、写入历史后、澄清后 | 直接对话回答，不进入 Excel/WPS 写入流程 |
| W-10 | 固化查询、历史计划、快捷命令与恢复按钮 | 当前授权重新核对，未开放的能力无法绕过 |
| W-11 | 服务中断、模型中断、取消、窗格刷新 | 状态准确，不重做未知副作用，不伪报完成 |
| W-12 | 窄/宽窗格、主题切换、长内容 | 沿用统一 UI，文字与操作不被裁切 |
| W-13 | Excel 与 WPS 同时使用本地服务 | 配置可共享，工作簿上下文、任务和执行权不串用 |
| W-14 | Excel 当前工作簿和文件夹模式回归 | 原有授权、查询、预览、写入和恢复不退化 |
| W-15 | 后续写入、部分失败、验证失败、人工修改后撤销 | 真实效果可核对，恢复不会覆盖后续修改 |
| W-16 | 后续故障续跑、重复点击继续、模型切换 | 同一身份续跑，已核验动作不重复执行 |
| W-17 | 用户安装包升级、卸载及未启用状态 | 正确提示，保留其他加载项和共享配置 |

自动化测试使用受控适配器样例，验证业务边界和数据标准化；真实 WPS 验证用于证明宿主 API、安装、窗格和保存行为。两类测试不能互相替代。

实施阶段提交前，按项目约定运行：

- npm run test:addin
- npm run build:addin
- .venv/Scripts/python.exe -m pytest server/tests -q
- .venv/Scripts/python.exe -m compileall -q server/app

后端测试使用隔离的 EXCEL_BRO_CONFIG_DIR 和新的测试临时目录，避免读取真实任务账本或复用包含用户资料的 pytest basetemp。

新增 WPS 构建入口后，再增加对应构建检查和上述人工验收。文档评审本身不代表这些测试已通过。
