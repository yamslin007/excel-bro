# 晚间讨论：EB 规则的产品定位反思（2026-08-08）

> 背景：用户在实际使用 RuleCreator 创建"最高错误级"规则时，暴露了一系列设计问题，进而引发对 EB 规则系统整体价值的讨论。

## 1. 起因：一个真实场景

**需求**：评分表中 D 列是"问题类型"（可能是多值，如"幻觉错误，语病问题"），E 列要填"最高错误级"。映射关系在"数据字典"工作表中：

| 问题类型 | 错误级别 |
|---------|---------|
| 无问题 | / |
| 空间方向 | p0 |
| 幻觉错误 | p0 |
| 人物指代 | p0 |
| 语病问题 | p1 |
| 运镜问题 | p1 |

**发现的问题**：EB 自定义函数是纯函数，运行时读不到"数据字典"表；且 `=EB(...)` 分发器参数声明为 `dimensionality: scalar`（rule_generator.py:200），传区域会被隐式交集截成单值。→ 字典无法作为参数传入，只能内嵌进函数逻辑。

**结论（当时的建议）**：字典仅 6 条且固定，应内嵌进逻辑，规则只保留 1 个参数（问题类型），用法 `=EB("最高错误级", D2)`。

## 2. 用户的第一个洞察：表单创建路径不好

> "我觉得这个函数的构造用这个页面去写并不好，直接在对话框里输入 `/function 问题描述`，自动捕捉表中信息给到大模型，大模型给出对应的函数，是不是更好"

**讨论结论：是的，且这本来就是设计文档的终态**（EB_FUNCTIONS.md 阶段 5"AI 集成"写的就是对话中创建规则，RuleCreator 表单只是过渡形态）。

对话框方案的优势：
- 生成时把上下文喂给模型（数据字典内容、D 列样本值），运行时纯函数的两难被解开
- 规则名、英文别名、参数全由 AI 推断，省掉表单

设想中需要抓取的上下文：
1. 当前选区（列头 + 前 N 行样本值）
2. 工作表列表（发现"数据字典"表则抓取其内容）
3. 已有规则名列表（别名查重、依赖）

交互流程：对话内预览卡片（名称/别名/参数/逻辑 + **用选区真实数据试算一行**）→ 保存。

需守住的约束：
- 生成的函数仍是纯函数，字典内嵌后字典表变更不会自动更新
- RuleCreator 表单保留为高级入口（手改逻辑、调试）

## 3. 用户的第二个洞察：EB 规则本身可能鸡肋

> "我现在反而觉得这个 EB 规则有些鸡肋，因为原来的需求，好像我也不需要它，也可以实现"

**讨论结论：这个感觉是对的。** "最高错误级"这种需求原生公式即可解决：

```excel
=IF(D2="无问题","/",IF(SUMPRODUCT(--ISNUMBER(SEARCH({"空间方向","幻觉错误","人物指代"},D2)))>0,"p0","p1"))
```

甚至不用公式——对话里说一句"帮我填 E 列"，AI 直接写值也行。

**EB 规则真正值钱的条件（三条同时满足才算）**：

1. **重复发生**：每周来一批同结构的表，同一套逻辑反复用
2. **数据会动**：行会增删、源数据会改，静态填值会过期
3. **原生公式表达不了**：正则、复杂文本处理（如"隐形字符清理"）

缺第 3 条 → 原生公式够；缺第 1、2 条 → 一次性 AI 填值够。标注评分场景大概率三条都不全占，所以感觉鸡肋是合理的判断。

## 4. 方向建议：收缩而不是废弃

保留"AI 生成逻辑"的核心能力，但**把出口从自定义函数换成原生公式**：

```
/function 根据数据字典算最高错误级
→ AI 生成原生 Excel 公式（或判断该直接填值）
→ 直接写进 E 列，完事
```

- 没有 manifest、没有运行时、没有重启生效；公式用户自己能看懂、能改
- 原生公式表达不了的（正则清理等）才落到 `=EB(...)` 重路径
- RuleCreator 表单、`#EB_RULES` 存储降级为"高级功能"，不推给普通用户
- EB 系统从"主力功能"退到"兜底能力"，对话 + 原生公式成为主路径
- 这也更符合既定原则："预制能力必须泛化"——最泛化的出口就是 Excel 自己的公式引擎
