## 🎯 核心设计

### 问题诊断

```python
# 当前 SDK 集成的问题根源
tools=[],  # ❌ 空的！
disallowed_tools=["Read", "Bash", "Write", ...],  # ❌ 全禁用
```

**结果：**
- ❌ Agent 无法探索数据
- ❌ 无法运行 Python 分析
- ❌ 被迫一次性猜测，准确率低
- ❌ 5 分钟超时，复杂任务中断
- ❌ 30 分钟会话失效

### 解决方案

```
释放 SDK 探索能力（Read + Bash + Python）
            ↓
通过 MCP 工具守卫最终写入
            ↓
保留三层安全防护（授权 + 白名单 + 确认）
```

### 架构设计（双宿主统一）

```
┌─────────────────────────────┐
│  前端（React）               │
│  ├─ Excel (Office.js)       │
│  └─ WPS (JSAPI)             │
│  → 统一数据格式              │
└───────────┬─────────────────┘
            │ HTTP POST
            │ {sheetsData: {...}}
            ▼
┌─────────────────────────────┐
│  FastAPI Backend             │
│  → 双宿主通用，无需区分       │
└───────────┬─────────────────┘
            │
            ▼
┌─────────────────────────────┐
│  Claude Agent SDK            │
│  ├─ Read (临时文件)         │
│  ├─ Bash (Python 分析)      │
│  └─ MCP (受控 Excel 访问)   │
└─────────────────────────────┘
```

## 🎓 关键洞察

### 为什么改造 SDK 而非移除？

**SDK 的核心价值：**
1. 完整的 Agent 能力（多轮推理、工具组合）
2. 进程隔离和临时目录管理
3. 未来可集成更多 MCP 工具

### 为什么选择"前端读取 + 请求携带"？

**对比其他方案：**
- ❌ WebSocket 反向请求 - 实现复杂
- ❌ 文件夹模式 - 只支持磁盘文件
- ✅ 请求携带 - 简单、通用、双宿主友好

**优势：**
- Office.js 和 WPS JSAPI 都在前端
- 本地网络传输快
- 后端无需区分来源
- 协议完全统一

### 安全边界如何保持？

**三层防护：**
1. **授权层** - MCP 工具验证表名
2. **白名单层** - 只接受合法动作类型
3. **确认层** - 用户预览后才执行

**改造不降低安全：**
- ✅ SDK 只能读授权的表
- ✅ 写入必须通过白名单
- ✅ 用户始终有最终控制权
