# 当前表授权交互三态修复（2026-10-08）

## 根因与范围

原共享守卫将“元数据一致但需显式分析同意”强制归为 `unavailable`，弹窗又把首次确认、身份缺失和真正变化全部显示成原文件/当前文件二选一。弱 WPS 包装对象的首次请求因此也被描述成“重新确认”；一次临时读取失败立即清除同意并打开弹窗。

本批同时修改 Excel/WPS 共用的守卫与弹窗，两端接入重新检查按钮。不以打开文件、同名、同表头替代授权或身份核验；不修改模型/服务端协议、文件夹权限或写入执行器。

## 新语义

- `confirmation_required`：元数据与全部可得身份键一致，但需要明确的分析同意。只显示一份文件/表范围和“确认范围并继续”，不展示重复文件选项。按钮仍重读实时元数据和身份证据，确认前不读字段或数据。
- `unavailable`：读取失败、证据缺失或证据冲突。只显示待核实范围和“重新检查”，不能通过确认按钮覆盖身份失败。临时缺失在后台做有限重试，默认 `authorizedTarget.verificationAttempts=2`；中途不撤销既有同意。重试耗尽或任意已得证据冲突时立即暂停并撤销弱同意，保留输入，不循环自动重试。
- `file_changed` / `scope_changed`：确实检测到文件/授权表变化，仍显示原目标与当前目标的显式选择；没有预勾选，不扩大原授权。重新检查中发现真正变化同样转入这一路径，不能悄悄采纳当前文件。

普通追问复用当前会话内已确认范围，仍逐条复核。弱同意不跨关闭/重载恢复。重新检查仅可继续已排队的新分析请求；被拦截的旧写入/业务计划没有重放回调。字段/源值读取、AnalysisPlan 白名单、预览和独立写入确认不变。界面单份摘要采用静态卡片布局，不伪装成可选项，长文件名可换行。

重试只用于暂缺或读取异常；已有两份证据冲突时，即便第三份证据缺失，也不能重试到看似一致后放行。新状态仅为内存中的 UI reason，不落聊天历史/请求/账本，不新增服务端协议字段。

## 自动化证据与限制

- 首批六条新用例修复前失败，修复后通过；收尾“部分证据缺失不能掩盖其余证据冲突”先失败再修复。
- 共用守卫 40 条、弹窗 4 条；Office 实际适配器范围授权 5 条；WPS 实际面板、澄清恢复与真实 fetch 隐私链路 145 条通过。覆盖短暂失败、有限重试、持续缺失、首次单份确认、连续追问、直接调用确认不能越权、换文件、证据冲突与不重放旧写入。
- 全量 Excel 849、WPS 556、core 311；后端 1167 passed / 1 skipped。双端类型/构建、compileall、diff-check 核实；既有 WPS act、构建体积与 pytest cache 权限警告分列，skip 不算通过。
- 真实 Excel/WPS 窗格尚未操作，自动化不等于实机证据。保留既有改动，未提交、未打包、未操作真实用户工作簿。

## 更新与实机清单

刷新或重新打开 Excel/WPS 加载项即可，无需仅为本次前端变更重启 Python。旧消息不改写。

1. 当前文件首次需要弱证据确认时，仅显示一份明确工作表范围；确认后连续提问不重问。
2. 已确认范围内短暂核验失败后恢复，不显示重复授权；持续失败提供重新检查，不读取字段或数据。
3. 暂停期间切换真实文件/删除授权表，重新检查必须进入目标变化选择，不能自动分析新文件。
4. 确认范围后产生写入预览，仍须独立确认写回；关闭重载后不自动继承弱同意。
