# 工作日志 2026-08-24

## 主题：计划编辑器独立窗口实现

### 背景

用户反馈编辑脚本对话框在任务窗格内显示时空间受限（约 700px 宽），希望像"专注窗口"一样打开独立的大窗口进行编辑。

### 问题根因

当前的 `.plan-editor-drawer` 虽然使用了 `position: fixed; inset: 0`，但仍然**受限于任务窗格的宽度**。这不是 CSS 问题，而是架构问题——需要使用 Office.js Dialog API 打开独立的浏览器窗口。

---

### P2: 实现 PlanEditorDialog 组件（2h）

**新增文件：**
- `apps/excel-addin/src/components/PlanEditorDialog.tsx`

**功能实现：**
1. **Office.js 初始化**
   - 调用 `Office.onReady()`
   - 监听 `DialogParentMessageReceived` 事件
   - 发送 `plan-editor-ready` 信号

2. **消息协议**
   - `plan-editor-init`: 父窗口传递初始数据（plan + target + workbook）
   - `plan-editor-ready`: 子窗口就绪信号
   - `plan-editor-save`: 保存成功后传回更新的计划
   - `plan-editor-close`: 取消关闭

3. **状态管理**
   ```typescript
   type DialogPhase = "loading" | "editing" | "validating" | "error";
   ```

4. **编辑与保存逻辑**
   - 复用 `usePlanEditor` 的核心逻辑
   - 本地 JSON 解析 + `assertEditablePlan` 校验
   - 服务端 `validatePlan` 规范化
   - 工具模式：调用 `updateToolPlanTemplate`
   - 指纹重算（schema 指纹）

5. **兜底机制**
   - localStorage 存储初始数据（`EB_PLAN_EDITOR_PAYLOAD`）
   - 支持不支持 DialogApi 1.2 的环境

### P3: 父窗口集成 Dialog API（1.5h）

**修改文件：** `apps/excel-addin/src/App.tsx`

**改动点：**

1. **添加 Dialog 引用**
   ```typescript
   const planEditorDialogRef = useRef<Office.Dialog | null>(null);
   ```

2. **新增 `openPlanEditorDialog` 函数**（参考 `openFocusWindow`）
   - 检查运行环境（必须在 Excel 中）
   - 构建初始化消息载荷
   - 存储到 localStorage（兜底）
   - 调用 `Office.context.ui.displayDialogAsync`
   - 设置窗口大小：90% 高度、85% 宽度
   - 监听子窗口消息（ready / save / close）

3. **实现消息处理**
   - `plan-editor-save`: 更新消息中的计划 / 更新工具列表
   - `plan-editor-close`: 关闭窗口

4. **替换现有调用**
   - 消息编辑：`planEditor.open(plan, { kind: "message", messageId })` → `openPlanEditorDialog(...)`
   - 工具编辑：`planEditor.open(tool.planTemplate, { kind: "savedTool", toolId })` → `openPlanEditorDialog(...)`

5. **清理代码**
   - 移除 `<PlanJsonEditor>` 组件渲染
   - 移除 `usePlanEditor` hook 调用
   - 移除相关导入
   - 添加 Dialog 清理逻辑（`useEffect` cleanup）
