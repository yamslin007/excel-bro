# Excel Bro 基础模式退出产品入口实施指导

版本：v1.0 · 2026-09-24

状态：待评审、待实施。本文件不表示功能已改造完成。

## 1. 目标与产品判断

EB 的主要使用方式是用户配置服务地址、模型 ID 和 API Key，通过外部模型理解需求，由受控工具读取、计算和执行。

当前“基础模式”不是大模型，主要通过固定规则识别明确地址的清空、写值和写公式指令。它不能独立理解常见自然语言统计、筛选、分组需求；WPS 当前只读边界又使主要写入能力无法使用。将其作为模型选项展示，容易形成“已经选好模型，可以开始对话”的错误预期。

本次目标：从 Excel 和 WPS 的模型选择与首次使用流程中移除“基础模式”，保留确定性计算与执行能力；未配置模型时明确引导添加 API 模型。

## 2. 范围与不可越过的边界

### 本次必须完成

- Excel、WPS 模型列表只显示真实配置的模型连接，不再注入虚拟 `local` 选项。
- 未配置模型时提供“添加模型”入口，保留用户已输入的任务文本。
- 区分模型目录加载中、加载失败、加载成功但为空，以及已配置模型。
- 迁移旧的 `local` 选择记录，处理连接删除和失效选择。
- 对需要模型的请求给出明确的未配置或不可用错误，不静默切换规则模式。
- 保留数据授权、预览确认、确定性工具、备份与断点恢复边界。
- 更新帮助、文档及有意义的行为测试。

### 本次不自动扩大的范围

- 不删除 `query_table`、数据读取器、计算器、白名单执行器、撤销和恢复代码。
- 不将所有 `provider="local"` 全局替换或删除：结果来源为本地工具，不代表模型选择为基础模式。
- 不取消 EB 后台。当前后台负责模型配置、凭据管理、请求转发和任务协调，它不要求部署本地 AI 模型。
- 不改为在 WebView 中直接调用供应商 API，不把密钥放入聊天记录、URL、日志或浏览器持久存储。
- 不开放 WPS 写入、撤销、恢复和其他尚未验收的能力。
- 不把现有地址规则功能重新包装成完整“离线 Agent”。

本次首要工作是移除用户入口和自动降级。规则解析代码的物理删除应另行确认调用关系；共享工具不得随入口一起删除。

## 3. 当前实现依据

实施前再次核对代码；以下为编写时已确认的位置。

| 位置 | 当前行为 | 修改方向 |
| --- | --- | --- |
| `server/app/llm/config.py` | `model_catalog()` 注入 `local`；无配置时默认值为 `local`；`selected_model_config()` 以空配置表示基础模式 | 真实模型目录、显式空状态、旧 ID 兼容处理 |
| `server/app/planner.py` | 无模型配置时走 `_local_analysis()`；已有工具结果可由 `_local_data_tool_response()` 输出 | 普通 Agent 请求禁止静默进入基础模式；保留有明确来源的确定性结果处理 |
| `server/app/intent.py` | 无配置时可直接放行；另有确定性结构命令识别 | 为模型任务统一检查配置，保留授权与结构校验用途 |
| `apps/excel-addin/src/hooks/useServiceHealth.ts` | 初始模型列表含基础模式 | 初始空列表，单独表示加载及失败 |
| `apps/excel-addin/src/modelSelection.ts` | 保留当前有效选择，否则返回默认值 | 返回值必须对应有效连接，支持无可用模型 |
| `apps/excel-addin/src/hooks/useModelManagement.ts` | 刷新后默认值可回退到 `local`；创建器依赖读取设置成功 | 清理默认回退；确保模型添加表单可进入 |
| `apps/excel-addin/src/App.tsx` | 基础模式标签、帮助、引导、默认选择及模型菜单 | 用未配置状态与添加入口替代 |
| `apps/excel-addin/src/helpCommand.ts` | 帮助介绍地址命令、离线及本地模型 | 改为模型配置与 EB 使用说明 |

| `apps/wps-addin/src/WpsModelSettingsPanel.tsx` | 模型设置及后台状态提示 | 延续可填写、可重试的 API 配置交互 |
| `server/app/main.py` | 请求入口、模型检查、恢复接口 | 普通请求和恢复分别核验，防止漏掉流式路径 |

检查所有调用路径，包括 `/api/intent`、`/api/plan`、`/api/turn` 及其流式入口、公式模型、持久任务恢复。不得只修改下拉列表。

## 4. 目标交互

| 状态 | 展示 | 操作 |
| --- | --- | --- |
| 目录加载中 | 正在读取模型配置 | 可进入添加表单；不冒充已连接 |
| 目录加载失败 | 无法读取模型配置，并提供重试 | 不将失败当成“没有模型”；保留草稿 |
| 目录已加载且无模型 | 尚未配置模型 | 主入口“添加模型”；提交任务时引导配置并保留文本 |
| 模型已配置 | 显示当前连接名称和模型 ID | 按正常流程提交任务 |
| API 鉴权、限流、网络或模型错误 | 按实际错误给出可操作提示 | 重试、编辑或明确切换模型 |

“已配置”不等同于 API 当前可调用，只有实际测试或调用才能确认连接状态。

配置表单不因之前的后台离线标志而锁死。测试和保存应发起真实请求，以本次结果更新状态；请求进行中防止重复提交。字段缺失等必要校验仍应保留。

进入新建表单不应等待后台读取成功。若后台不可达，保留当前页面内的草稿，清楚说明保存尚未完成。关闭表单时沿用凭据清理策略，不为保留草稿而新增密钥持久化。

不要同时显示绿色 `Failed to fetch` 和红色错误提示。网络错误应统一、清晰地展示；提示不能声称已经测试了供应商 API，除非实际到达该步骤。

建议文案：

- 未配置：“添加一个模型连接后，即可通过对话查询和分析表格。”
- 配置页：“填写服务地址、模型 ID 和 API Key。密钥保存在这台电脑上。”
- 后台不可达：“暂时无法连接 Excel Bro 后台。已填写内容仍保留在当前表单中，请恢复连接后重试。”
- API 鉴权失败：“模型服务拒绝了当前 API Key，请检查密钥及服务地址。”

禁止使用“请启动本地 AI”“基础模式已就绪”“离线 · 零延迟”等误导性描述。

## 5. 模型选择与旧数据迁移

模型目录成功加载后，按以下顺序确定新任务的选择：

1. 用户本次明确指定且在目录中有效的模型。
2. 本机保存且仍有效的真实模型 ID。
3. 服务端声明且仍有效的默认模型 ID。
4. 目录中的首个可用真实模型。
5. 无可用模型时进入未配置或不可用状态。

旧 `local` 记录在目录成功加载后按上述规则迁移；连接断开时不得根据空列表删除原有效选择。删除当前模型后重新计算选择，删除最后一个模型后回到未配置状态。

前端展示、请求 modelId、存储选择必须一致。禁止界面显示首个真实模型，实际请求仍携带 `local`。

“首次目录尚未加载”“目录请求失败”“成功返回空目录”必须分别处理。模型目录接口不能以虚拟基础模式占位来掩盖失败。

公式模型的“跟随全局选择”可以继续保留；其含义是跟随真实模型。如果公式模型引用旧 `local` 或已删除连接，迁移为跟随全局，并在无真实模型时提示配置。

## 6. 服务端与协议

建议模型目录约定：无真实连接时 `models=[]`、`defaultModelId=null`。前端使用明确的无选择状态，不发送空串或 `local` 冒充有效模型。

实施时先检查现有接口约束及旧客户端兼容要求，再确定发布方式。改动涉及类型、响应或校验时，同步更新 `apps/excel-addin/src/contracts.ts`、`server/app/models.py`，以及实际定义模型目录、健康状态的 `api.ts` 和解析测试。不要仅改 TypeScript 类型。

建议区分 `MODEL_NOT_CONFIGURED`、`MODEL_NOT_AVAILABLE` 等稳定错误含义；复用已有错误协议，避免新增第二套格式。错误文案不包含凭据。

- 未提供 modelId：只允许解析到有效的真实默认模型；无配置时明确失败。
- 普通新任务携带旧 `local`：返回需要选择模型的明确错误；新前端负责预先迁移。
- 显式指定失效 ID：返回模型不可用，不静默调用另一供应商。
- API 调用失败：保持原任务状态并明确错误，不自动执行基础模式规则。

配置校验应覆盖需要模型的任务入口，而不是阻断所有后台功能。健康检查、模型设置、已有结果查看、确定性工具及恢复资料访问不应被全局模型校验拦截。

确定性结构命令识别仍可用于授权及安全校验。是否需要模型由入口契约决定，不得因一个早返回分支让普通 Agent 请求重新进入基础模式。

## 7. 保留确定性能力及恢复语义

- 模型负责语义与工具参数，本地工具负责数据读取和准确计算。
- 用户选择的工作表仍为不可扩大的授权边界，意图阶段不上传原始数据行。
- 所有写入继续使用白名单 AnalysisPlan，先预览、后确认。
- 已存在且验收过的固化工具可继续独立运行；不要因移除基础模式而强制它们调用模型。
- WPS 未开放的固化工具不能因本次重构自动出现。
- 历史消息、结果中的 `provider=local` 保持可读。
- 已批准计划的确定性执行与恢复不能因模型入口调整而被无故阻断。
- 规划恢复若需要模型，只能按既有规则由用户明确选择接管连接，并保留 turnId、checkpoint、幂等约束及原授权。
- 旧 checkpoint 含 `local` 时按阶段判定：需要语义规划的任务引导选择模型；纯执行阶段核验已有计划与现场。不得把旧任务当新请求重新运行。

## 8. 分阶段实施

### A：状态与兼容基础

梳理模型目录、健康状态、选择存储、公式模型与恢复调用链；定义无模型协议、状态及迁移规则，完成对应行为测试。

### B：Excel 与 WPS 界面接入

移除基础模式选项、初始化占位和相关提示；实现添加模型空状态、任务草稿保留、目录重试、可填写的配置表单；两端选择逻辑采用同一规则。

### C：清理隐式降级与回归

修复服务端新任务无配置时的规则降级，核验流式/非流式与恢复入口；整理帮助、过时文案及文档。共享确定性功能保留。

每阶段记录修改、验证结果及剩余问题。除非用户另有要求，阶段完成后继续后续阶段；出现需要改变架构或扩大能力的决定时再提出具体问题。

## 9. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 新安装，无 API 配置 | 没有基础模式选项，显示添加模型入口 |
| 已有真实连接、存储为 local | 目录成功加载后迁移到有效真实连接，展示与请求一致 |
| 模型目录加载失败 | 显示失败及重试，不断言用户没有连接，不覆盖旧选择 |
| 删除当前/最后一个连接 | 正确选取其他有效连接/回到未配置状态 |
| 无模型时提交自然语言统计 | 引导添加模型，保留任务输入，不生成写入计划 |
| 配置有效模型后统计 | 外部模型理解、本地统计、对话回答，结果与数据一致 |
| API Key 无效或供应商断开 | 显示本次错误，不回退基础模式、不伪造成功 |
| EB 后台断开后打开设置 | 能进入并填写表单；测试、保存能重试并准确反馈 |
| 填写后后台恢复 | 草稿未丢失，实际保存/测试可成功，旧离线标记不锁死按钮 |
| Excel 明确写入需求 | 仍须预览并确认，授权与备份行为不变 |
| WPS 明确写入需求 | 保持现有拒绝执行行为 |
| 已固化工具、旧本地来源结果 | 原有可用能力及历史展示不受损 |
| 暂停任务、切换模型继续 | 恢复同一现场，不重新执行已完成步骤 |
| 窄侧栏及模型设置弹层 | 入口可点击，无遮挡，关键提示完整可读 |

测试优先覆盖状态转换、真实点击、请求 ID 和错误结果，避免只匹配源代码字符串、或用正则未匹配返回空串的方式伪造按钮已启用。

运行项目要求的测试与构建：

```powershell
npm run test:addin
npm run build:addin
npm run test:wps
npm run build:wps
python -m pytest server/tests -q
python -m compileall -q server/app
```

真实宿主分别验证 Excel、WPS；文件夹模式验证选择与无模型行为。自动测试通过不能代替宿主验收；未完成项明确记录。
