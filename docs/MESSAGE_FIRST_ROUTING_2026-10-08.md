# 先理解消息，再按需读取字段（2026-10-08）

## 原因与新流程

此前 Excel 发送先调用 captureWorkbookStructure，WPS 先 readSchemas，再请求意图模型。
所以感谢、问候也会扫描字段，进度先显示读取后显示理解。Excel 初始化还存在自动结构扫描。

新消息的共同流程：

1. 模型仅理解当前消息、最近六条纯文本对话和附件数量。不自动附带文件名、工作表名、字段、
   原始数据行、priorResult 或 priorIntent。当前输入优先于旧任务，通用知识和感谢可直接回复。
2. conversation 直接结束，不进入目标授权检查、结构扫描、本地计算或规划。后台的
   身份元数据监测是独立安全机制，不读单元格，也不因聊天撤销已有同意。
3. needs_workbook_context 后核对当前授权；目标变化或证据不足先确认，确认前字段、
   数据行、字段意图与规划请求、写入均为零。理解模型本身不构成数据或写入授权。
4. 在授权边界内读取结构，再结合字段判断澄清、查询或白名单写入计划。
   查询确定后才读数据进行本地确定性计算；写入仍先预览、再单独确认。

消息理解失效、超时、取消或协议错误不能默认为工作簿任务。结构修复最多两次，
截断立即失败。图片数量不代表看过图，附件仍交给原有后续视觉规划，不新增图像出站。
授权弹窗续跑可复用当前消息的理解结论，但重新核对真实目标；不复用旧结构或私有规则。
理解、目标核对及后续规划共用取消信号；阶段交接不短暂解除运行状态，避免重复发送或
停止后又继续读字段。

## 接线与边界

- 新 POST /api/intent/message：独立于 /api/turn 与规划任务账本。请求 extra=forbid；
  双宿主共享 TS 协议、实际 JSON 投影和严格响应校验，服务端 models.py 同步。
- 普通模型和 Claude SDK 用同一消息提示词与结果协议；SDK 权限不扩展。
- Excel 启动/范围刷新只 captureWorkbookCatalog（文件/表名目录，无 range/values）；
  真正任务按授权调用 captureWorkbookStructure。WPS 本身的目录入口仍只读元数据。
- Excel 当前工作簿、WPS 当前工作簿及 Excel 文件夹发送均使用第一阶段。
  文件夹的用户主动选择/扫描行为不改；任务阶段只使用用户明确选择的结构。
- 已有业务补全、确定性工具、执行恢复及写入审批不改为自动执行；它们仍复核授权。
  明确 /function 命令仍走既有专用受控流程，不新增通用模型路由。
- 聊天只一次模型请求；工作簿任务增加一次无结构理解请求。这是按需读取的实际代价，
  不能用改步骤标题或本地关键词判断冒充先理解。

## 验证与重启

自动化覆盖真实 Excel/WPS 组件发送、低层 WPS 顺序、实际 fetch 字节白名单、目录零
range/values、无效/截断响应失败关闭、理解期间换文件及取消零字段读取。两模型后端
测试捕获实际提示载荷；未使用真实付费模型或操作真实工作簿，不代表实机体验已验证。

新增服务端接口，需重启本地 Python 服务，再刷新 Excel/WPS 加载项；旧后端不能自动
回落为先读字段。没有启用 Python 执行产品开关、没有打安装包或提交 Git。

最终回归：Excel 821 条、WPS 555 条通过；两端构建与类型检查通过；服务端全量
1149 passed / 1 skipped，compileall 通过。跳过项是既有 Windows 符号链接权限
用例，不计作通过。WPS 既有 act 测试警告和构建大包警告仍存在。

清空旧选择，确认仍重新检查身份。新增两条用例在旧逻辑下均失败，恢复修复后
两条及授权守卫 31 条通过；没有放宽读取或写入授权。
