# 基础模式退出：配套提示词

配套方案：`docs/BASE_MODE_RETIREMENT_GUIDE.md`。

## 1. 实施提示词

```text
请在 Excel Bro 项目中实施 docs/BASE_MODE_RETIREMENT_GUIDE.md。

开始前阅读 AGENTS.md、docs/ARCHITECTURE.md、docs/DEVELOPMENT.md 和上述指导文件，检查工作区已有修改，然后核对方案与当前代码的差异。

目标：从 Excel 和 WPS 的模型列表、默认选择、首次引导中移除“基础模式”；用户通过服务地址、模型 ID 和 API Key 配置外部模型。未配置时显示“添加模型”，保留任务草稿。不要把本机 EB 后台称为本地 AI。

按指导文件的 A、B、C 阶段连续实施，不要只改 UI 或文案：
1. 定义无模型、目录加载失败等状态；迁移旧 local 选择，统一真实模型选择规则，保证界面和请求 ID 一致。
2. 两端添加表单不依赖后台读取成功才能进入；测试/保存允许真实重试，后台不可达时保留表单内草稿并准确反馈；请求进行中防重复提交。
3. 为普通 Agent 入口处理无模型与失效模型错误，覆盖流式、非流式、公式与恢复路径；禁止静默降级或静默换供应商。
4. 保留确定性读取、计算、白名单执行、固化工具及恢复能力，不能全局删除 provider=local，也不能删除 checkpoint 或重新运行旧任务。

不改变 EB 后台架构，不改为 WebView 直连供应商，不新增浏览器密钥持久化。不要开放 WPS 未验收的写入等能力。协议变化同步 TypeScript、Python、API 解析与测试。

实现能验证状态和交互结果的测试，尤其覆盖旧 local 迁移、目录请求失败、删除最后一个连接、离线填表后重试、无模型统计请求以及恢复同一任务。不要用源码字符串匹配代替行为测试。

运行指导文件列出的测试和构建，更新受影响的架构、开发和 README 文档。需要用户在 Excel/WPS 点击验收时给出具体操作，未验证的项目如实列出。

保留用户已有改动，不输出 API Key。不要自动 git 提交、推送或打包安装程序。最终报告：实际完成范围、验证结果、剩余宿主验收项和重要兼容性影响。
```

## 2. Claude / 其他评审者提示词

```text
请评审 Excel Bro 的 docs/BASE_MODE_RETIREMENT_GUIDE.md，并结合仓库现有实现核实可行性。此轮只评审，不修改运行时代码。

产品目标已确定：模型入口面向用户配置的外部 API 模型，不再展示“基础模式”。确定性读取、计算、执行及 EB 后台基础设施应保留。

重点检查：
- 模型目录空状态、加载失败、已配置与实际可调用是否被正确区分；
- 旧 local 选择、默认模型、连接删除、公式跟随选择的兼容性；
- 界面展示与实际 modelId 是否可能不一致；
- 无模型请求是否仍会从意图、规划或结构命令早返回分支静默降级；
- 配置入口、后台恢复后的重试、草稿与密钥处理是否完整；
- provider=local 的结果来源是否与基础模式入口被混为一谈；
- 固化工具、已批准计划、断点恢复及模型接管是否会受损；
- Excel、WPS、文件夹模式是否均有适当覆盖，是否误开放 WPS 写入；
- 协议迁移与测试要求是否可落地。

按严重程度给出具体问题，引用仓库文件及函数，解释触发条件、影响和建议修正；区分已确认缺陷与需要进一步验证的推测。不要仅复述方案或提出没有依据的架构重写。

将评审写入 docs/REVIEW_BASE_MODE_RETIREMENT_GUIDE.md，保留原指导文件。结论说明能否开始实施、必须先修正哪些问题、哪些可随实施处理。
```
