# Excel Bro 数据流程优化开发计划

> 文档状态：已完成  
> 最后更新：2026-07-29  
> 适用范围：当前工作簿、文件夹批处理、固化工具、执行与验收流程

本文用于记录数据流程优化的实施顺序、依赖关系和完成标准。开始任务前应同时阅读
[架构说明](./ARCHITECTURE.md)与[开发指南](./DEVELOPMENT.md)。

## 1. 优化目标

- 当前工作簿使用 Office.js/TypeScript 处理实时和未保存的数据。
- 文件夹批处理使用 pandas 做确定性计算，openpyxl 负责文件写回、格式、备份和验证。
- 模型只负责语义判断，不直接执行 JavaScript、Python、VBA 或宏。
- 用户选择的工作表和文件始终是不可扩大的授权边界。
- 固化工具重复运行时优先完全本地执行，减少模型 API 调用。
- 写入继续遵循“结构化计划 → 预览 → 用户确认 → 执行 → 真实验证”。

## 2. 目标数据路径

| 使用场景 | 语义判断 | 数据读取与计算 | 写入 | 验证 |
| --- | --- | --- | --- | --- |
| 当前打开的 Excel | 首次需求由模型判断 | Office.js 分块读取，TypeScript 确定性计算 | Office.js 白名单动作 | Office.js 重新读取 |
| 文件夹中的工作簿 | 首次需求由模型判断 | pandas 读取授权数据并计算 | openpyxl 写入临时文件 | openpyxl 重新打开验证 |
| 当前工作簿固化工具 | 通常不调用模型 | TypeScript 按参数实例化和计算 | Office.js 白名单动作 | Office.js 重新读取 |
| 文件夹固化工具 | 通常不调用模型 | pandas 按参数执行 | openpyxl 写入临时文件 | openpyxl 重新打开验证 |

已完成的主干能力：

- 大数据聚合不再使用可能导致参数栈溢出的展开调用；
- 字段访问已预编译为列索引，并补齐 25 万行及关键单元格类型测试；
- 工作簿和文件夹模式会在写入前预检整份计划；
- 执行失败会区分已成功、失败和未执行动作；
- 验证结果已区分 `verified`、`executed_unverified` 和 `failed`；
- 排序会检查执行后的真实值顺序，筛选和表格会读取保存后的对象状态；
- 常用格式、边框、数据验证和冻结窗格会读取保存后的真实属性；
- 当前工作簿的图表和数据透视表会核对真实数据源、位置和对象配置；
- 只有独立验证通过的计划才能保存为固化工具。
- 文件夹写入先全部保存到同目录临时文件，再备份并原子替换；
- 预览数据具备来源指纹，执行前变化会阻止旧计划；
- Office.js 查询按块读取，提供进度、取消、结构缓存与缓存失效；
- 文件夹完整查询由受控 pandas 适配层执行，支持合并、去重、关联和分组；
- 固化查询可在当前工作簿或文件夹模式重复本地执行，并记录模型调用次数；
- 诊断导出只包含阶段、耗时、读取量、状态和错误分类。

## 6. 每项任务的完成标准

任务只有同时满足以下条件才可标记为“已完成”：

- 没有扩大用户选择的工作表或文件授权范围。
- 意图阶段没有新增原始数据行上传。
- 没有引入任意 JavaScript、Python、VBA、宏或外部程序执行。
- 写入仍需先展示结构化预览并由用户确认。
- 协议变化已同步 TypeScript 与 Pydantic。
- 当前工作簿和文件夹模式的支持情况已经明确。
- 新缺陷有可复现测试，关键边界有回归测试。
- 相关架构、开发指南和 README 已同步。
- 以下命令全部通过：

```powershell
npm run test:addin
npm run build:addin
python -m pytest server/tests -q
python -m compileall -q server/app
```

## 7. 明确不做的事情

- 不保存或执行模型生成的任意 JavaScript/Python。
- 不允许 pandas 接收未经服务端授权解析的文件路径。
- 不让固化工具绕过预览、确认和验证。
- 不为提高性能而降低工作表授权、协议校验或写入安全要求。
- 不在第一阶段同时重写 Office.js、文件夹模式和固化工具，避免变更范围失控。
