# WPS W3 写入、验证与撤销实施指导

> 状态：代码闭环已实施，等待目标 WPS 真实宿主验收
> 适用版本：WPS 表格个人版 `12.1.0.28488`
> 前置阶段：W0、W1、W2 已完成并通过真实 WPS 验收
> 目标：在不破坏 Excel Bro 既有安全边界的前提下，为 WPS 当前工作簿增加最小、可验证、可撤销的写入闭环。

## 1. 文档用途

本文件是 WPS 适配阶段 W3 的执行文件。开发、评审和验收均以本文件为准。

总原则继续遵循：

- 模型只负责语义判断和生成白名单 `AnalysisPlan`，不直接操作工作簿。
- 工作簿读取、计算、写入、验证与撤销均由本地确定性代码完成。
- 用户选择的工作表是不可扩大的授权边界。
- 所有写入必须先生成预览，再由用户明确确认。
- 写入前必须成功保存可恢复的前状态；无法恢复时禁止执行。
- 验证失败不等于“没有写入”，必须保留撤销入口和真实状态。
- 不执行任意脚本、VBA、宏、COM 自动化或外部程序。
- 不使用 openpyxl 兜底修改 WPS 当前打开的工作簿。
- 不自动保存用户工作簿，也不把磁盘副本冒充为当前内存工作簿的撤销快照。

## 2. W3 首版范围

### 2.1 首批开放能力

W3 首版开放 `writeValues`，并把 `clearRange(applyTo=contents)` 降解为同一套空值矩阵写入：

- 目标为当前 WPS 工作簿中已经存在的工作表。
- 目标工作表必须已被用户授权。
- 目标使用明确的 A1 矩形区域。
- 输入只允许 JSON 标量矩阵：字符串、数字、布尔值和空值。
- 输入矩阵尺寸必须与目标区域完全一致。
- `clearRange` 只允许 `contents` 且不得带筛选条件；格式、超链接和结构删除仍拒绝。
- 支持覆盖空白、常量和公式单元格，但撤销快照必须能区分并恢复原公式。
- 执行完成后重新读取目标区域，进行独立验证。
- 当前任务中提供一次或多次撤销，撤销深度沿用项目统一能力配置。

### 2.2 首版明确不做

- 新建、删除、重命名或拆分工作表。
- `clearRange` 的 `all`、`formats`、`hyperlinks` 或带筛选条件形式，以及排序、筛选、去重、格式化、合并单元格。
- 写公式、图表、透视表、数据验证、批注、图片或外部链接。
- 对 `.xls`、`.xlsm`、`.et`、云文档或尚未保存的工作簿执行写入。
- 修改受保护工作表、合并单元格区域或无法稳定定位的区域。
- 后台自动保存、静默覆盖或绕过确认。
- 断点恢复后自动重放不确定的写入。无法确认现场时必须进入待核对状态。

后续动作必须逐项补齐“预检、预览、快照、执行、验证、撤销、异常恢复”后才能加入白名单，不能只实现写入函数。

## 3. 开始编码前的硬门禁

### 3.1 WPS JSAPI 能力探测

先在目标 WPS 版本中验证并记录以下能力：

1. 获取当前工作簿、活动工作表和工作表集合。
2. 获取稳定的工作簿身份信息；优先使用本地完整路径和文件名。
3. 读取指定区域的值、公式、行列数和地址。
4. 写入二维值矩阵。
5. 区分空白、常量和公式单元格。
6. 检测工作表保护状态、合并单元格和只读状态。
7. 在写入异常后重新读取已写入区域。
8. 在任务窗格刷新后判断是否仍是同一本工作簿。

探测结果必须写入新的 W3 验证记录。如果无法获得稳定工作簿身份，首版写入能力保持关闭，不以文件名作为唯一身份强行开放。

### 3.2 开放条件

只有同时满足以下条件，界面才可显示“可写入”：

- 当前宿主确认为 WPS 表格且版本在已验证范围内。
- 当前文件是已保存的本地 `.xlsx`。
- 工作簿身份、工作表身份和授权范围可稳定取得。
- 本地服务、计划协议和 WPS 执行器版本兼容。
- 写入动作在 WPS 白名单中。
- 快照存储可用且可在写入前持久化。
- 当前没有未解决的部分写入或恢复冲突。

任一条件不满足时保持只读，并向用户说明具体原因。

## 4. 复用现有架构，不建立第二套 Agent

WPS W3 应复用现有对话、模型连接、`AnalysisPlan`、预览确认、任务检查点和执行时间线。WPS 只增加宿主适配和确定性执行能力。

推荐职责边界：

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| 模型/规划层 | 理解用户意图，生成白名单计划 | 直接调用 WPS JSAPI、输出任意脚本 |
| 计划校验层 | 校验动作、授权、尺寸、目标和能力 | 自动扩大工作表授权 |
| WPS 宿主适配层 | 读取、快照、写入、验证和恢复 | 根据自然语言自行决定写哪里 |
| 检查点/日志层 | 保存执行状态、快照引用、异常和重试信息 | 把“请求已发送”记为“写入成功” |
| UI 层 | 展示预览、确认、真实状态和撤销入口 | 验证失败时隐藏已经发生的写入 |

现有只读查询链路保持不变。`怀化横店电影城有多少条记录` 等只读请求不能因为 W3 上线而进入写入流程。

## 5. 建议文件落点

先核对实际入口和共享模块，再按下列职责组织；文件名可根据现有结构调整，但不能混合职责。

### 5.1 WPS 前端

- `apps/wps-addin/src/wpsHost.ts`
  - 补充宿主版本、工作簿身份、可写状态和能力探测。
- `apps/wps-addin/src/wpsWorkbookReader.ts`
  - 保持确定性读取；增加供快照与验证复用的范围读取能力。
- 建议新增 `apps/wps-addin/src/wpsPlanExecutor.ts`
  - 只接受已经通过校验和确认的 `AnalysisPlan`。
- 建议新增 `apps/wps-addin/src/wpsWriteSnapshot.ts`
  - 负责前状态、后状态指纹和恢复数据的序列化。
- 建议新增 `apps/wps-addin/src/wpsUndoManager.ts`
  - 负责撤销栈、冲突检查、恢复和恢复后验证。
- WPS 页面入口组件
  - 增加计划预览、确认、状态展示和撤销入口，不复制 Excel 页面业务逻辑。

### 5.2 共享协议与服务端

- 优先复用现有 `AnalysisPlan` 和执行检查点结构。
- 现有 Office.js 恢复登记要求 `url:` 身份并拒绝来源表与目标表重合；WPS 本地文件
  不满足这两项约束。复用同一任务账本时必须增加明确的宿主类型和 WPS 专属身份校验，
  不得伪造 `url:` 或放松 Office.js 原有校验。
- 如果增加字段，必须同步修改：
  - `apps/excel-addin/src/contracts.ts`
  - `server/app/models.py`
- WPS 动作白名单、最大单次写入单元格数、最大撤销条目数等项目限制放入 `config/capabilities.json`。
- 检查点中保存快照引用和执行状态，不把完整原始数据发送给模型。
- 如果需要新增服务接口，接口只服务本地确定性执行和恢复，并补充协议测试。

### 5.3 不应修改的边界

- 不把 WPS JSAPI 代码放入服务端。
- 不让服务端通过文件路径修改当前打开的 WPS 工作簿。
- 不把 WPS 特例写进通用意图提示词来代替确定性能力判断。
- 不改变 Excel 当前工作簿和文件夹模式的既有行为。

## 6. `writeValues` 计划约束

首版计划至少包含或可确定得到：

- `executionId`：一次用户确认后的执行标识。
- `actionId`：动作级幂等标识。
- `actionType`：固定为 `writeValues`。
- `targetWorkbookId`：稳定工作簿标识。
- `targetSheetId` 或稳定工作表标识。
- `targetSheetName`：仅用于展示和二次核对，不能单独作为身份。
- `targetAddress`：规范化 A1 矩形地址。
- `values`：与目标等尺寸的二维标量矩阵。
- `sourceFingerprint`：规划时授权数据的指纹。
- `targetPreconditionFingerprint`：确认前目标区域指纹。
- `expectedPostFingerprint`：由本地代码基于目标内容计算。

校验规则：

1. 不支持的动作导致整份计划被拒绝，不允许静默跳过后继续执行。
2. `splitBy`、`groupBy` 等分析语义不能在 WPS 执行器中临时解释为写入动作。
3. 目标工作表必须在授权集合内。
4. 目标范围越界、矩阵不规则、尺寸不符或单元格数超限时拒绝。
5. 字符串以 `=` 开头时首版按普通文本还是公式必须由协议明确；首版建议拒绝，等待独立公式动作。
6. 合并单元格、受保护工作表、只读工作簿或不稳定身份均拒绝。

## 7. 写入前快照

### 7.1 快照最小字段

每个动作在首次写入前必须保存：

- `executionId`、`actionId`、动作序号。
- 宿主类型与 WPS 版本。
- 工作簿身份、工作表身份、工作表名称。
- 目标 A1 地址、行列尺寸、单元格总数。
- 每个单元格的原始类型：空白、常量或公式。
- 原值和原公式；只保存恢复所需数据。
- 写入前指纹。
- 计划写入内容的指纹。
- 创建时间、状态和校验版本。

`writeValues` 不修改格式，因此首版无需复制整张工作表或所有格式；但覆盖公式时必须保存公式本身，不能只保存公式计算结果。

### 7.2 快照状态

建议使用以下状态：

- `creating`：正在读取和组装快照。
- `ready`：快照已完整持久化，可以执行写入。
- `applying`：已经开始修改工作簿。
- `applied`：所有计划写入已提交，尚未完成验证。
- `verified`：独立验证通过。
- `written_unverified`：写入发生但验证未通过或中断。
- `undoing`：正在恢复。
- `restored`：恢复并验证通过。
- `reconcile_required`：现场不确定，需要用户核对。

只有 `ready` 状态允许进入首次写入。

### 7.3 存储要求

- 优先接入项目已有的任务检查点和执行日志，不新建互不兼容的恢复体系。
- 快照必须在本机持久化，不能只存在 React state 或临时闭包中。
- 写入前持久化失败必须中止执行。
- 快照数据不得发送给模型。
- 快照保留、容量和条目数使用统一配置；清理不得删除仍处于活跃、未验证或可撤销状态的记录。

## 8. 标准执行流程

### 8.1 预览阶段

1. 解析并校验 `AnalysisPlan`。
2. 检查 WPS 宿主能力和工作簿身份。
3. 检查目标工作表授权。
4. 读取目标范围并生成写入前指纹。
5. 展示文件、工作表、区域、单元格数量和前后值摘要。
6. 明确提示这是 WPS 写入操作，可在当前恢复记录有效期内撤销。
7. 等待用户确认；取消时不创建写入动作。

### 8.2 确认后执行

1. 生成或锁定 `executionId` 和 `actionId`。
2. 再次检查工作簿、工作表、授权和前置指纹。
3. 读取并持久化完整前状态快照。
4. 将快照标记为 `ready`。
5. 将执行状态标记为 `applying`。
6. 按配置的单次最大单元格数或分块大小写入。
7. 每一块成功后记录块级进度；不得只记录总动作开始。
8. 全部写入完成后标记为 `applied`。
9. 重新读取完整目标区域并独立比较。
10. 验证通过后标记为 `verified`，向用户报告真实结果。
11. 验证失败时标记为 `written_unverified`，保留并突出显示撤销入口。

模型调用结束、网络中断或 UI 重新渲染均不能改变已经发生的写入事实。

## 9. 独立验证

验证必须重新通过 WPS JSAPI 读取工作簿，不能复用待写入矩阵作为结果。

首版验证至少包括：

- 工作簿和工作表身份仍然一致。
- 返回范围地址和尺寸一致。
- 每个目标单元格与期望类型和值一致。
- 完整目标区域指纹与 `expectedPostFingerprint` 一致。
- 写入区域之外未被本动作声明的区域不纳入“已验证成功”结论。

状态文案应区分：

- `验证通过`：写入且独立读取一致。
- `已写入，验证未通过`：工作簿可能已改变，允许撤销。
- `部分写入，可恢复`：已知完成了部分块，允许撤销。
- `现场待核对`：无法判断最终状态，暂停后续写入。

禁止把“工具调用无异常”直接显示为“验证通过”。

## 10. 撤销流程

### 10.1 撤销前冲突检查

撤销前重新读取目标区域：

- 当前内容等于动作的写入后指纹：允许自动恢复。
- 当前内容等于写入前指纹：说明已经恢复，按幂等成功处理。
- 当前内容两者都不等：说明用户或其他动作又修改了该区域，禁止自动覆盖，进入冲突状态。

### 10.2 恢复与验证

1. 加载对应动作快照。
2. 校验工作簿、工作表和目标区域身份。
3. 标记为 `undoing`。
4. 按单元格原始类型恢复空白、常量和公式。
5. 重新读取目标范围。
6. 与写入前快照逐项比较并校验指纹。
7. 验证通过后标记为 `restored`。
8. 恢复失败时保留快照，报告失败位置，不删除撤销记录。

撤销成功后才能淘汰对应恢复数据。栈淘汰和过期清理遵循项目统一的备份/恢复清理规则。

## 11. 幂等与断点恢复

恢复调度加载检查点后，对每个动作执行以下判断：

| 当前目标状态 | 处理方式 |
| --- | --- |
| 等于写入后指纹 | 跳过重复写入，继续验证或后续节点 |
| 等于写入前指纹 | 可按原 `actionId` 重新执行 |
| 只完成了已记录的前 N 个块 | 从下一块继续，完成后做全量验证 |
| 与前后指纹均不一致 | 停止自动恢复，进入 `reconcile_required` |
| 工作簿身份变化或文件不存在 | 停止恢复，提示用户打开原工作簿 |

切换模型只能替换后续模型节点，不能重新创建执行任务、丢弃 `executionId` 或从头重放已完成写入。

## 12. 异常处理矩阵

| 异常时机 | 状态 | 用户可见结果 | 后续处理 |
| --- | --- | --- | --- |
| 快照完成前 | `failed_before_write` | 未修改工作簿 | 可重试 |
| 快照已就绪、首次写入前 | `ready` | 未修改工作簿 | 可继续或取消 |
| 分块写入中 | `partial_write_recoverable` | 可能部分修改 | 优先撤销或从已知块继续 |
| 写入完成、验证前中断 | `written_unverified` | 已写入，结果待确认 | 重新读取验证 |
| 验证不一致 | `written_unverified` | 已写入但验证失败 | 保留撤销入口 |
| 撤销中断 | `undo_failed` 或 `reconcile_required` | 恢复未确认 | 保留快照并人工核对 |
| 用户修改了目标后再撤销 | `undo_conflict` | 不自动覆盖用户新内容 | 提供冲突说明 |

发生不确定状态后，禁止对同一工作簿继续执行新的写入计划，直到完成核对或恢复。

## 13. UI 要求

### 13.1 只读与可写状态

- W3 未开放或门禁未通过时继续显示“WPS 只读”。
- 门禁通过后显示“WPS 可写入”，并说明“写入前会预览并要求确认”。
- 不因模型回答包含“已修改”字样而切换宿主状态。

### 13.2 预览卡片

必须展示：

- 文件和工作表。
- 目标区域。
- 动作类型。
- 影响单元格数量。
- 写入前后摘要；大量数据只展示受控样本，不泄露敏感值到日志。
- “确认写入”和“取消”按钮。

### 13.3 执行过程

按真实顺序展示：

1. 写入前检查。
2. 撤销快照已准备。
3. 正在写入第 N/M 块。
4. 正在重新读取验证。
5. 验证通过、验证失败或待核对。

工具名称、动作、目标和状态不得隐藏。长卡片继续使用项目现有的顶部/底部收起逻辑。

### 13.4 撤销入口

- 任何已经发生写入的非成功状态都必须显示撤销入口。
- 验证失败不能隐藏撤销按钮。
- 冲突时撤销按钮改为“查看冲突”，不得继续自动覆盖。
- 任务窗格重开后，如果恢复记录仍有效，应恢复状态与入口。

## 16. 首版验收标准

只有全部满足时，W3 才能标记完成：

- 用户未确认时绝不写入。
- 写入目标无法超出用户授权的工作表。
- 写入前存在完整、可读取的恢复快照。
- 执行结果由重新读取验证，不由模型自报成功。
- 验证失败时如实显示“已写入，验证未通过”。
- 已经发生写入时始终提供有效撤销或冲突处理入口。
- 撤销可正确恢复原空白、常量和公式。
- 重试、模型切换和任务窗格刷新不会重复写入。
- 不确定现场会暂停，而不是猜测并继续。
- WPS 只读能力、Excel 当前工作簿模式和文件夹模式回归通过。

## 17. 实施顺序结论

严格按以下顺序执行：

1. W3-A 能力探测与协议冻结。
2. 评审探测结果；任一硬门禁不满足则停止。
3. W3-B 实现底层执行闭环。
4. W3-C 接入预览确认和 UI。
5. W3-D 实现撤销、故障注入和恢复。
6. 完成真实 WPS 验收后再进行 W3-E 灰度开放。

不要先开放按钮再补撤销，也不要一次加入多个写入动作。首个动作完整闭环通过后，再逐项扩展 WPS 白名单。
