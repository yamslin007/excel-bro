# 澄清与重新授权循环修复（2026-10-05）

## 源码根因

- WPS 作答前先复核宿主对象，unknown 分支返回时没有把真正的答案写入任务恢复记录。
- 正常续答更新了旧卡片，但下一轮 `carried()` 默认取空确认数组，造成新的澄清卡丢失前面已提交的回答。
- 本地映射表单提交的结构化规则只在函数参数里，身份复核失败就销毁澄清状态；重新授权后只重跑原需求，模型再次给出同一份未补全规则。
- WPS 工作簿和工作表包装对象不保证引用稳定。引用不同应保持 unknown，不能自动判 same，也不能谎称文件已改变。
- Excel 本地映射的身份不足分支同样删除了草稿，要求重发需求，而不是保留补全结果并提供确认入口。

## 已实现

- WPS 普通选项和自定义回答先记录真实答案，再核对授权。下一轮与历史恢复沿用 taskId、原始需求和全部确认信息；模型问题使用返回的 clarification.id 定位答案。
- WPS 本地补全规则仅在当前窗格内存中按 messageId 保存。身份 unknown 时提示已提交规则、等待重新授权；授权后重新读取真实源列，直接本地计算并生成新预览，不再重启模型。
- 本地规则仅在授权索引、范围身份、表头仍匹配，且路径或稳定表 ID 没有正面变化证据时续接。同名异路径、表替换或范围变化不得挪用私有规则。
- Excel 身份不足时保留 pendingRule，提供“确认此范围并生成预览”。点击后重新读取授权表结构；仍读不到身份则停住，已知身份或范围冲突仍废弃旧规则。
- 计算失败保留本地补全结果供再次确认范围后重试；重新读取发现新的来源缺口时仍按真实缺口询问。
- 预览阶段不写原表；本地来源值、补全规则和目标值矩阵不进入模型请求或对话持久存储。没有协议变更，没有扩大授权。

## 验证

- WPS 新增真实新包装 getter 测试（工作簿与工作表每次访问均返回不同引用），完整点击“提交补全 → 确认范围 → 预览”，fetch 次数不增加，原表写入次数为 0；私有哨兵确实在来源格与表单内，请求体和持久历史均不包含哨兵。
- WPS 连续澄清、重开恢复和 unknown 作答测试覆盖真实回答的逐轮携带，原需求不会重复拼接确认信息。
- Excel 共享表单测试覆盖确认入口实际点击及原填值保留；全量 Excel 回归通过。未以此宣称真实 Office.js 宿主链路已验收。
- 三次独立反向变异：禁用本地续接、取消答案携带、移除跨路径守卫，分别使对应新用例变红；已全部还原。
- 全量回归：Excel 731 / 69 文件，WPS 437 / 29 文件，core 216 / 15 文件，服务端 790 通过；两端构建、服务端 compileall 和 diff 检查通过。定向 lint 无错误，7 条既有 Hook 依赖警告；保留既有 React act 告警，无环境阻断。变异还原和最终提示/失败重试修改后全量 WPS 再跑 437 通过。

## 未实现与实机待验

- 私有本地规则跨关闭恢复未实现：它们不落盘。关闭窗格后只能重新读取、重新询问必要的本地补全，不冒充已恢复私有答案。
- 不硬编码等级、字段、行业映射或分组方式。新的真实缺口仍需澄清；空白策略不冒充复合类别的拆分和优先级规则。
- 真机待验：在独立测试工作簿重复用户任务，提交空白保留、逐行映射及必要的复合类别规则后到达预览；确认范围不得重问已答问题，写入前仍需用户确认。
- Excel/WPS 均需实机核对重新授权、宿主包装对象变化和源数据变化时序。本轮未调用真实模型、未操作客户工作簿、未提交或打包。
- CAP-02 未推进；CAP-03 精确续跑剩余动作未实现，不改为“待实机验收”。
