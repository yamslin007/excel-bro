## 阶段 1：`/function` 短链主路径（已 Excel 实测通过）

### 设计定案
- **短链生成**：绕开 planner 的 intent→create_plan 重链，命中式单发生成，类比 `/commit`。
- **双版本公式**：模型一次返回**现代版(365/2021)+兼容版(2016/2019)两条公式**，预览卡切换开关，默认选兼容版（用户原则"兼容不是禁用，是给出选择"）。
- **预览卡交互**：首格真实试算 → 确认后写整选区 → 复用 `runPlan` 撤销。

### 后端
- `server/app/rule_generator.py` 新增 `generate_formula` 全套：
  - `GenerateFormulaRequest` / `GenerateFormulaResponse`（4 字段：modernFormula/modernExplanation/compatFormula/compatExplanation）、`DictionarySheet`。
  - `_build_formula_generation_prompt()`：系统提示固化多条通用约束，防模型踩坑。
  - 解析器带优雅早返回：两版公式皆空但有 explanation 时，直接回传说明而非报错。
- `server/app/main.py`：新增 `POST /api/formulas/generate` 端点。

### 前端
- `App.tsx`：`FunctionPreview` 卡（双版本试算 + 版本切换开关 + 应用/撤销）、`handleFunctionCommand`、`applyFunctionPreview`。
- `api.ts`：`generateFormula()` 客户端。
- `contracts.ts`：`GenerateFormulaRequest/Response`、`FormulaDictionarySheet` 类型。

### 关键 bug 修复：`#VALUE!` 数组错误
真实场景（评分表按数据字典算"最高错误级"）中，现代版公式 `COUNTIF(levels,"p0")` 报 `#VALUE!`。
- **根因**（非"抽象失败"）：`COUNTIF/SUMIF` 的区域参数必须是**真实工作表区域**，不能喂 `TEXTSPLIT/XLOOKUP/FILTER` 产生的内存数组或 `LET` 变量。
- **修复**：在生成提示里加两条**通用**约束——
  1. `COUNTIF/COUNTIFS/SUMIF/SUMIFS` 区域参数不能喂内存数组/LET 变量。
  2. "判断单元格含清单任一关键词并归类"首选 `SUMPRODUCT(ISNUMBER(SEARCH(关键词区域,目标格))*(级别区域=某值))>0` 整块运算，而非切分逐查。
- 用户实测反馈："amazing！！！有"。

## 阶段 2-4：删自定义规则链 + RuleManager 只读化

### 关键再定案（用户本轮拍板）
- **用户永远不新增 EB 规则**。表单向导、AI 生成 JS 规则逻辑（`generate_rule` 链）整条删除。
- 预制规则（`CLEAN`/`EMPTY`）硬编码保留，`=EB()` 运行时照常执行；用户只"触发"和"了解"，不创造。
- `/function` 的 `=EB` 回退收敛：**仅可引用 CLEAN/EMPTY 两个预制，绝不编造规则名**；连预制也表达不了 → 返回空公式 + explanation 提示"原生做不了，请在对话中描述走常规 intent→create_plan 处理"。

> ⚠️ 过程中一度混淆"删表单"与"删 JS 能力"，被用户及时拦下（`/function` 产原生公式 vs `generate_rule` 产 `=EB()` 执行的 JS，是两种不同能力）。厘清后确认删除方向正确。

### 后端删除
- `rule_generator.py`：删 `generate_rule` 链（`RuleParam`/`GenerateRuleRequest/Response`/`_build_rule_generation_prompt`/`_extract_dependencies`/`_compile_rule_logic`）、metadata regen 全套（`ALIAS_PATTERN`/`_DISPATCHER_ENTRY`/`FunctionsMetadata*`/`RegenerateFunctions*`/`functions_json_path`/`regenerate_functions_metadata`）。
- `main.py`：删端点 `POST /api/rules/generate`、`POST /api/rules/functions-metadata`。

### 前端删除
- 整删文件：`RuleCreator.tsx`、`RuleManager.integration.example.tsx`、`ebDependencies.ts`、`ebDependencies.test.ts`。
- `api.ts`：删 `generateEBRule`、`regenerateFunctionsMetadata`。
- `contracts.ts`：删对应 6 个类型。
- `ebStorage.ts`：塌缩为单个 `loadRulesFromSheet()`（只返回 `BUILTIN_RULES`），删 `saveRule/deleteRule/exportRules/importRules/checkAndRestoreRules/getRulesStats` 及 `#EB_RULES` 隐藏表全套机制。
- `RuleManager.tsx`：砍成**只读函数说明**（搜索框 + 内置函数列表 + `RuleCard`），删所有增删改导入导出刷新 handler、`RuleCreator` 渲染。
- `ebRules.ts`：`EBCategory` 收成仅 `'builtin'`。
- `functions/functions.ts`：删运行时自定义别名注册块（`loadRules().then(...)`，已成空转）。

### 保留内核（manifest 绑定 / 运行时）
`functions.html`、`commands.html`、`functions.json` 静态分发器、`functions.ts` 的 `=EB` 分发器 + 预制别名注册、`BUILTIN_RULES`(CLEAN/EMPTY)、`getBuiltinFunction`、`loadRulesFromSheet`、`validateAlias`/`ALIAS_PATTERN`/`isBuiltinRule`（仍供 `ebRules.test` 用）。
