# 文件夹范围安全与交互修复（2026-10-08）

本批修复 Excel 现有文件夹链路，不新增 WPS 文件夹入口、不开放隔离 Python、不提交或打包。WPS 当前工作簿功能保持不变；文件夹入口仍是明确未实现项，不标成“实机待验”。

> **后续更新（2026-10-16）：WPS 文件夹入口的「选择 + 授权」这一段已实现**（选目录、文件/表两级勾选、承认汇总、确认才提交、草稿与取消、刷新增表不作废 / 换目录与目标消失即作废），与 Excel 同一套口径、共用 `packages/core/src/folderScope.ts` 的判据；工作目录范围下发送侧明确拒绝且零工作簿读取。
> 本节第 3 条记的 `preserveAuthorization` 语义（同根 + 同会话 + 目标都在才保留确认）就是 WPS 侧复用的那一份，**没有**为 WPS 另写一套。
> **仍未实现**：WPS 面板到服务端查询/执行通道的接线、以及真实 WPS 实机验收 —— 与本节第 4 条「所选文件已在 Excel 打开」的那套宿主读取无关，WPS 文件夹模式的数据读写全在服务端 openpyxl，不经宿主写入适配器。

## 实际改动

1. `create_folder_snapshot` 对全部选中文件读取前、读取后分别计算内容指纹；读取期间任何变化都拒绝快照。只有一致性检查成功后才发布新授权与来源指纹，失败保留原已确认现场。既有执行前文件指纹检查、白名单计划、备份与回读不变。这是前后内容一致性检查，不是对外部进程的文件锁或原子文件系统快照。
2. 共享纯函数 `packages/core/src/scopeFingerprint.ts` 将绝对目录根路径纳入本地澄清范围绑定；不同路径的同名目录不再相等。Windows 大小写/分隔符兼容、UNC 主机保留、POSIX 大小写保留，缺少绝对根身份失败关闭。Office 自动模式仍绑定活动表，手动模式不因移动光标失效。路径只在本地比较，不增加模型/API 请求字段；旧的无根路径文件夹澄清记录拒绝续答。
3. 候选目录刷新显式使用 `preserveAuthorization`：只有同根、同会话且全部已选目标仍存在时保留原确认；草稿从不因此变成授权。换目录/会话、已选目标消失仍取消确认，新增表不自动勾选。点击“工作目录”切换模式不凭 localStorage 勾选自动授权。会话重建只重放本面板内明确确认过的范围，不能读取新增草稿表；重载后保存的勾选需要重新确认。重新选择目录与普通候选刷新采用不同路径。
4. 所选文件已在 Excel 打开时，先用 `captureWorkbookCatalog` 取得名称，再仅对明确勾选的表调用 `captureWorkbook(selectedNames)`；范围“刷新”也改用目录捕获，不读取活动表数据。

没有修改服务端/前端协议，没有把路径加入 `IntentScopeContext`；授权仍是用户明确选择的工作表，写入仍须独立预览与确认。共享目录身份纯函数及后端快照保护可由未来 WPS 文件夹适配复用，不等于 WPS 本轮已有文件夹能力。
