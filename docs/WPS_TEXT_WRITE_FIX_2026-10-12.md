# WPS 数字文本写入保真（2026-10-12）

## 实机反馈

用户在生成审阅副本时得到：`汇总表!A1:G9`，首个差异 `D8`，计划为文本、回读为数值，原表未写入。此前仅有范围级错误，不足以定位；本轮增加的单元格坐标/类型诊断未输出实际单元格内容。

这是宿主写值时发生类型转换的证据，不能通过把数字与数字文本视作相等来解决，否则会丢失 `007` 的前导零或长编号精度。不能把本次现象归咎于模型没有生成计划。

## 修复

新增 `wpsWriteMatrix.ts`，由 WPS 原生审阅副本、正式执行器、撤销恢复共用。对计划中的文本单元格，先取得原 NumberFormat，临时设为 `@` 后赋值，finally 恢复原格式并回读格式验证。数值、布尔值、null 保持原类型；恢复矩阵中的真公式不设为文本。全部格式在首个修改前读取，设置格式失败不开始赋值，恢复某格失败也继续尝试恢复其他格，然后明确报错。

依据：[WPS 桌面 JSAPI Range 官方文档](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Range/obj) 的 NumberFormat 接口。临时文本格式对本机宿主的实际效果仍需用户重试确认，替身测试不当实机证据。

严格的值/公式回读、授权检查、预览确认、原表与副本隔离不变。不追加新的模型调用，不改计划的值或验收矩阵，不自动二次写入纠正读回差异。

旧宿主若无法取得逐格 NumberFormat，沿用原写入通道及严格回读；不能保证此类宿主的数字文本保真，不声称该分支已修复。格式恢复失败会报错，不显示成功；若宿主已拒绝恢复格式，不能承诺格式一定已恢复。

## 验证与端别

- WPS 替身实现按 NumberFormat 将数字文本转数值，覆盖副本 → 原表确认执行 → 回读 → 撤销。`7`、`007` 为文本，400 为数值，原目标 `0009` 撤销后仍是文本；数字格式恢复。
- 类型不符、null/空字符串不符、同类型不同内容仍拒绝，原表零写入、失败副本关闭。
- 独立写入适配测试覆盖长编号、单格标量赋值、混合类型、写入失败、格式设置失败、格式恢复被静默拒绝、公式/数值格式不受影响。
- WPS 全量（新增异常测试前）：689 passed / 1 skipped；build（含 tsc）成功。新增三个异常测试后，写入适配/副本/执行器合计 63 passed。
- Excel 使用 Office.js `range.values`，本轮未修改其适配器。未新增跨端业务协议/能力，未取得真实 Excel 的类型保真证据，不以 WPS 修复宣称双端实机验收完成。
