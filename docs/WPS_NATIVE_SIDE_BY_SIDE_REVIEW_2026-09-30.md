# WPS 原生并排审阅：原表与独立副本

状态：**已接线并通过自动化；2026-09-30 真机首次点击在复制前被误拒，身份判断已修正，完整流程仍待重新实机验收。**

## 用户确认的交互

1. 左侧是未修改的原工作簿；右侧是 `Worksheet.Copy()` 生成的**独立、未保存工作簿**，不是同一工作簿的 `NewWindow()` 第二视图。
2. 计划预览后点「生成右侧副本并排审阅」：只在副本上按白名单计划试写、回读，在实际变化单元格上标浅绿底色。随后从原表窗口调用 `Application.Windows.CompareSideBySideWith(copyWindowName)`，并请求同步滚动；Excel Bro 对话仍在右侧任务窗格。
3. 点「放弃副本」只用 `copy.Close(false)` 丢弃副本。点「确认写回原表」先复核副本结果和原表预览指纹，再交给原有 `executeWpsPlan` 写入原表、保存恢复点并回读。**不是**直接把副本文件覆盖原文件，也不会自动保存副本。
4. 写回后的原表计算值若与副本不同，明确警告并保留撤销入口；公式文本匹配并不等于计算值相同。

### 参数化列映射的公式优先（2026-09-30）

同表、非空文本来源且公式分支数/长度在 `config/capabilities.json` 的
`columnMappingFormula` 上限内时，本地确定性计算先给出预期值，再构造逐行
`IF(EXACT(源格, 分类), 结果, …, NA())` 公式。规则中的整格类别与本次实际出现的
组合均可命中；未知的新组合明确显示 `#N/A`，不猜测等级。它不是对任意未来
分隔组合的通用公式承诺。右侧未保存副本试写后必须同时核对**公式文本**与
`Value2` **计算结果**；任一不符或宿主不提供计算值，关闭试写副本，再以本地
确定性结果生成固定值副本供用户重新审阅。原表仍只在用户确认后写入。
空白、非文本来源、跨表计划、公式安全校验或长度上限不满足时直接用固定值。
Excel 当前工作簿通道尚无写入前隔离试算，仍用固定值；文件夹模式仍用服务端
确定性固定值。两者不可被称为已完成公式优先对齐。以上为自动化验证，WPS
真机公式试算、自动回退、最终写回后的计算值仍待独立测试工作簿验收。

## 边界与失败方式

- 当前原生审阅只开放**单张已授权工作表**；多表计划明确拒绝，不复制整个工作簿来绕过授权。计划及副本矩阵只留会话内存，不进 URL、服务端、聊天历史或 `PluginStorage`。恢复点仍由原表执行器按现有规则管理。
- WPS `Worksheet.Copy()`、`Workbook.Activate()`、`Workbook.Close(false)`、`Windows.CompareSideBySideWith(name)` 和 `Range.Interior.Color` 依据官方 ET API 声明接线；类型存在不等于本机验收通过。宿主无法证明新对象是独立副本、复制前后值不符、并排 API 返回失败或缺底色接口时，一律不写原表。
- 首次真机点击「生成右侧副本并排审阅」在 `Copy()` 前报「当前活动工作簿已不是预览时的原表」，确认原表未写入。原因是并排审阅额外使用了 `ActiveWorkbook === 预览时的 JSAPI 包装对象`；同一本已保存工作簿在不同读取中可能得到不同包装对象，引用比较不是稳定身份。该路径现改为核对预览时的工作簿名、完整路径、目录、授权表及目标/来源快照，且继续由原执行器在正式写入前复核；副本身份记录创建时的名称/路径，保存成磁盘文件后不得继续当作待审阅副本。**这不改变待答澄清对未保存工作簿采用的保守对象引用判据。**测试已模拟每次读取返回新包装对象，并断言同名异路径仍在复制前拒绝。
- 若审阅期间用户改动原表或副本，写回前拒绝；不能把旧预览、旧副本或编辑后的副本悄悄当成已确认计划。关闭副本失败时不声称已清理，要求用户手动关闭且不要保存。
- 面板刷新会丢失内存里的待审阅会话；副本可能仍由 WPS 保持打开。此时不得从历史消息恢复「保存变更」按钮，用户须手动处理副本并重新生成计划。
- 已验证的结果卡不再打开旧的窄任务窗格 HTML 双网格；失败诊断仍可用旧的回读明细，不能冒充原生并排审阅。

## 真机验收（只用独立测试文件）

1. 准备已保存的本地 `.xlsx`，只勾选一张测试工作表；记录原文件保存前状态。启动 WPS 开发加载项，生成一个包含值或公式写入的计划。
2. 使用本轮修正后的开发服务刷新任务窗格，点「生成右侧副本并排审阅」。首先确认不再出现上述复制前误拒；再确认出现**两个不同工作簿**，原表在左、副本在右、聊天任务窗格仍可操作；检查原表值和格式未改变，副本目标值已变化且只有变化坐标有浅绿底色。横向/纵向滚动时核对同步。
3. 一轮点「放弃副本」：副本关闭且不弹保存结果，原表仍未变化。再生成计划，重复审阅后点「确认写回原表」：原表才写入，副本关闭，验证卡与恢复点出现，可撤销。
4. 分别在审阅期间手工修改原表目标格、修改副本目标格，确认两种情况都拒绝写回且不自动覆盖任何内容。再测公式计算值与副本不一致时的明确警告。
5. 测跨表计划：原生并排入口应拒绝并解释限制。测关闭/刷新任务窗格：不能出现可复用的旧保存入口；若副本还在，按提示手动关闭且不要保存。

完成这些操作前，只能说「自动化通过、待实机验收」，不能声称 WPS 已按用户截图完成原生布局。相关官方 API：[Worksheet.Copy](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Worksheet/member/Copy)、[Windows.CompareSideBySideWith](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Windows/member/CompareSideBySideWith)、[Window.Close](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Window/member/Close)。
