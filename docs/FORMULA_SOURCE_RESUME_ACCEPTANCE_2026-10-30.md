本包只做一件事：把**公式计划**的跨重启恢复在真实 Excel 与真实 WPS 上各走两遍（A、B）。
每端两条独立执行，做完一轮即可收尾；**不要求**重复已经通过自动化的项目（§7 列了哪些不用再点）。

## 1. 入口核实结果（先看结论，再看操作）

确定性中断入口是窗格底部的「恢复验收（开发专用）」→「启用下一次第二步中断」，判据唯一出处
`packages/core/src/recoveryProbe.ts`（两端只按引用调用，没有第二份）。

**核实结果：它原本不支持公式计划。** `bindRecoveryProbe` 的绑定闸要求"三个独立单格的 `writeValues`"，
`writeFormulas` 一律 fail-closed。也就是说在本次改动之前，公式续跑**根本没有确定性中断入口** ——
只能用"手动杀宿主"这种不可复现的方式，那不算证据。

本轮只把**这条验收工具**的形状闸门扩成"值或公式的单格写入"（`writeValues` / `writeFormulas`，都必须是 1×1）：

| 判据 | 改前 | 改后 |
| --- | --- | --- |
| 动作条数 | 必须 3 | **不变** |
| 相邻单格 | 必须三格互异（`sheet!首格` 去重后仍是 3） | **不变** |
| 可恢复资格 | `recoverable` 必须为真 | **不变** |
| 工作簿身份 | 必须与 arm 时同一份已保存工作簿 | **不变** |
| 动作类型 | 三动作都必须是 `writeValues` + 1×1 `values` | `writeValues`+1×1`values` **或** `writeFormulas`+1×1`formulas` |
| 不合规时 | 写入前取消验收并抛错，**零写入** | **不变**（文案补成"（值或公式）"） |

产品判据（授权边界、来源证据、覆盖核对、恢复材料、账本）**一行未改**。工具改动只影响"能不能挂上中断"。

**入口能在公式计划上生效的前提**（不满足就 fail-closed，一格都不写）：

- Excel：这份计划必须已登记可恢复。2026-10-31 修复后，纯公式计划由客户端在首次执行前，按公式的静态跨表依赖读取已授权来源表并登记 `sourceDependencySheets` 和指纹；不再依赖模型是否调用读取工具。读取失败或读取期间身份/授权变化时零写入。混合固定值计划仍沿用原规划证据；续跑不能现读补基线。
- WPS：`resumeContext` 必须存在 —— 即第二轮补上的**来源覆盖证据**已经随登记落盘。

## 3. 独立夹具（新建一份，别在真实业务表上做）

新建 `公式来源证据验收.xlsx`（先保存），四张表：

| 表 | 内容 |
| --- | --- |
| `来源` | 固定矩形 **A1:B5**：A1..A5 = 10, 20, 30, 40, 50；B1..B5 = 1, 2, 3, 4, 5 |
| `结果1` | A1 = `target-1`（标记用），**B2 留空** |
| `结果2` | A1 = `target-2`，**B2 留空** |
| `结果3` | A1 = `target-3`，**B2 留空** |

纪律：

- 「来源」**不要**被本计划写入（依赖表同时是写入目标 ⇒ 不登记精确恢复）；
- 三张结果表必须**各不相同**（探针要求三个互异单格的独立动作；同一张表连续三格很容易被合成一个区域动作）；
- 只勾这四张表：`来源`、`结果1`、`结果2`、`结果3`。

## 4. 任务原文（两端同一段，原样发送）

```
先读取 来源 表的 A1:B5。然后按顺序执行三个独立的公式写入动作，每个动作只写一格：
1）结果1 的 B2 写公式 =来源!B2*1
2）结果2 的 B2 写公式 =来源!B4*2
3）结果3 的 B2 写公式 =来源!B5*3
必须写成公式（不要写算好的数值），必须分别保留为三个动作、不合并范围、不加格式、不改来源表。
按正常流程直接执行并回读，再展示结果供审阅。
```

两处不是随口加的：

- **「先读取 来源 表的 A1:B5」**：仍是用户要求的读取任务。恢复资格另由本机实际读取建立证据：纯公式计划不因模型遗漏工具读取而直接失去恢复资格；模型声称“已读”不能作为证据。两端均由宿主适配层采集依赖表证据，原授权及来源变化阻断保持不变。
- **三张不同的结果表**：见 §3 的第三条纪律。

顺带核过一条可能静默失败的前提：`=来源!B2*1` 这种**中文表名、不带引号**的公式，判据
`formulaDependencies` 解析成 `{sheets:["来源"], local:false, dynamic:false, external:false, unresolved:false}`
（`='来源'!B2*1` 同解）—— 也就是说这三条公式本身不会因为"解析不出依赖"被拒绝登记。
真正的门槛是本机确实取得来源证据，以及 `来源` 不能同时是写入目标。

## 5. 每端两条独立执行

A、B 是**两次独立执行**（各用一份干净夹具，或 A 收尾后把三张结果表的 B2 清空再用同一份文件）。不要在同一次执行里连做。

### 5.A 中断 → 完整退出重开 → 核对 → 续跑 → 只写第三步 → 确认

| # | 操作 | 期望 / 记录什么 |
| --- | --- | --- |
| A1 | 展开底部「恢复验收（开发专用）」→ 点 **「启用下一次第二步中断」** | 状态变「已启用：仅作用于当前工作簿的下一次执行。」 |
| A2 | 发送 §4 任务原文 | 先看到读取与预检，然后开始逐动作执行 |
| A3 | 等到中断 | 面板/对话出现 **「恢复验收：第二步已写入并回读，已在完成回执前中断；第三步未执行。请重开窗格并核对后续跑。」** 记录三格：`结果1!B2`、`结果2!B2` 是公式；`结果3!B2` **仍为空**。此时**不要**点放弃/撤销、不要重发需求 |
| A4 | 保存 → **完整退出宿主**（Excel 关 Excel 进程；WPS 退出 WPS 表格）→ 从磁盘重开同一文件 → 重开窗格（后端保持运行） | 窗格里出现恢复卡：「上次写入的恢复核对」 |
| A5 | 若数据范围面板还没勾好：勾同样这四张表并确认 | 授权集合与原执行一致 |
| A6 | 看恢复卡状态 → 点 **「核对在途动作」** | Excel 预期「待核对在途动作」→（核对后）「可继续剩余动作」；WPS 重开后一般直接给「可继续剩余动作」。核对本身**零写入**：三格不变 |
| A7 | 点 **「继续剩余动作」** | 只补第三步。断言：`结果3!B2` 出现 `=来源!B5*3`；`结果1!B2`、`结果2!B2` **没有重写**（Excel 看执行记录/`office_host_writes` 里只有 `idx2`；WPS 看结果卡里已核对的动作只有一格） |
| A8 | 审阅条点 **「确认变更」** | 状态「已确认变更」；恢复卡与操作条消失；三格仍是三条公式 |

### 5.B 重开后先改来源 → 续跑被拒 → 目标不变 → 放弃恢复

前半段与 A 一样（A1–A5），关键是**改来源必须发生在点续跑之前**。

| # | 操作 | 期望 / 记录什么 |
| --- | --- | --- |
| B1 | 同 A1–A5：启用中断 → 发任务 → 断在第二步 → 保存 → 完整退出重开 → 勾同样的表 | `结果1!B2`、`结果2!B2` 已有公式，`结果3!B2` 空 |
| B2 | **在点续跑之前**：把 `来源!B5` 改成 `500`（它正好被第三步公式 `=来源!B5*3` 引用；顺手确认 `来源!A1:A5` 其它格别动） | `来源!B5 = 500` |
| B3 | 点 **「继续剩余动作」**（WPS 若先显示「核对在途动作」，就先核对再续跑） | **拒绝**，文案 **「来源已变化，不能沿用旧结果续跑。」**；`结果3!B2` **仍是空**；`结果1!B2`、`结果2!B2` 原样；`来源!B5` 仍是 500（没有被写回） |
| B4 | 记录此刻入口的真实状态（**按实际写，不为了出现"继续"按钮去改现场**） | Excel：失败后卡片换成「需要人工核对」，只剩「清除这条恢复提示」—— 这是既定语义（证据不够就不给写入/补记按钮）；WPS：卡片可能仍显示「继续剩余动作」，再点仍是同一句拒绝 |
| B5 | 放弃并验证恢复（两条路，按现场“有哪个”走） | 见下面 5.B-1 / 5.B-2 |

**5.B-1（重开后窗格里仍有撤销入口）**：点执行记录卡上的 **「撤销本次执行」**（WPS 是结果卡上的撤销）
⇒ 三张结果表的 `B2` 回到**写前（空）**，`来源!B5` 保持你改的 `500`，对话出现「已撤销「…」，并回读确认恢复成功」。

**5.B-2（重开后没有撤销入口 —— 预期就是这一条）**：Excel 只在执行 `completed` 时重建撤销栈，
中断执行跨重启后通常没有「撤销本次执行」。这时**如实记录**"重启后没有可用撤销入口"，然后在**同一会话内**补做一次：

1. 重新启用「启用下一次第二步中断」→ 发 §4 任务原文 → 断在第二步（`结果1/2!B2` 有公式）；
2. 把 `来源!B5` 改成 `500`；
3. 点「继续剩余动作」→ 同一句拒绝（零写入）；
4. 点 **「撤销本次执行」** → 三格回到写前，`来源!B5` 保持 500。

这条对应自动化里的「续跑被拒之后，放弃仍能把原值恢复回来（拒绝不等于卡死）」——
拒绝只挡"继续写"，不挡"退回去"。

> 若 5.B-2 的撤销也失败或按钮不存在，**停在这里并保留现场**，把界面文案与账本状态记下来，不要手改单元格。

## 6. 看到「恢复验收已取消」怎么办

文案：**「恢复验收已取消：需要当前工作簿中已登记可恢复的三个独立单格写入（值或公式）；未执行写入。」**

含义：这次计划不是"三个互异单格的独立动作"，或者它本来就没被登记为可恢复。**本次一格都没写**。

处置顺序：

1. 重新启用中断，把 §4 的任务原文再发一次（重点保留"每个动作只写一格 / 不合并范围"）；
2. 仍被取消，就把"本次未形成三动作"记下来，**不要**手改计划、不要为了凑形状去改宿主或授权；
3. **不要**用"连发三条消息各写一格"来代替 —— 那是三次执行，不构成同一份计划的三动作续跑。
